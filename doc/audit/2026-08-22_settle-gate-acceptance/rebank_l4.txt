all of the above.

  1. the settle default (hand-set 60 -> committed 40, fabric gated 128/128 + 288/0 before capture)

     the harness defect that produced 48 spurious L4 diffs last night)

that is an HTTP status from the kernel, not a strictness setting: the (src,dst) pair was absent
from the kernel's path map. The suspected cause there is the known non-monotonic
all_destination_paths fetch (16256 dropping back to 13184), which is intermittent by
construction -- so a single passing run is exactly the evidence that cannot distinguish "fixed"
from "did not happen to hit it this time".

P1-3 therefore stays open with its status downgraded from "reproducible 404" to "did not
reproduce at the fixed default, n=1". Closing it needs repetition, not this run.
