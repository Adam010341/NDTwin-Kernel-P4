### 2.4 「第一次取樣」什麼時候發生——**對安靜的鏈路：永遠不會**

寫入點只有一個：`TopologyAndFlowMonitor.cpp:1189`（`updateLinkInfoLeftLinkBandwidth`，`:1142`）

```cpp

```

它的兩個呼叫端都在 `FlowLinkUsageCollector.cpp`：

| 呼叫端 | 迭代的容器 |
|---|---|
| `:1991`（主速率迴圈，host→switch／switch→switch） | `m_counterReports` |
| `:1699`（`creditHostBoundEgressEdges`，switch→host） | `m_egressCounterReports` |

而在 **MININET 模式下**，這兩個 map **只由 flow sample 填**：

- `FlowLinkUsageCollector.cpp:1443-1459`：`if (m_mode == utils::MININET) { m_counterReports[…] += frameLength * samplingRate; }`
  （`:1446` 是 ingress 那筆，`:1459` 是 `m_egressCounterReports` 那筆）
  — 在 **flow sample** 分支（`sampleType == 1 || 3`）裡。
- `FlowLinkUsageCollector.cpp:1102-1107`：**counter sample** 分支在 MININET 模式下
  `continue`，**在 `:1120` 碰 `m_counterReports[agentIpAndPort]` 之前就跳掉**。
  （counter sample 那一路的 map 寫入在 `:1119-1120`，MININET 永遠走不到。）

🔴 **結論（推翻條目的一半敘述）**：
一條**從來沒有流量**的邊，**永遠不會有 `m_counterReports` 條目**，
⇒ `updateLinkInfoLeftLinkBandwidth` **永遠不會為它跑**，
⇒ `leftBandwidthFromFlowSample` **永遠停在 1 Gbit/s**。

> **與條目對帳**：KNOWN-ISSUES F-8 寫「**F-8 是暫態、會被真資料取代**」。
> **那句只對「曾經有過流量」的邊成立。** map 條目一旦建立就不再刪除（全 repo 無 `m_counterReports.erase`），
> 所以「有過流量、現在安靜」的邊每輪都會被更新成 `linkBandwidth - 0` ＝ 正確值；
> 但**從頭到尾安靜的邊是永久錯誤，不是暫態**。
> ⇒ 建議把條目的「暫態」改成「**在有流量的邊上是暫態；在從未有流量的邊上是永久**」。
> 這一改會影響 §D 那類「反正會被真資料蓋掉」的裁定理由。
