### 2.4 這條缺陷把它上游那條修正整個抵銷掉

`classifyFlowStatsReply`（`:984`）與 `kFlowStatsSuspectSeconds`（`hpp:317`）是為了 2026-08-07 那次
「Ryu wedge ⇒ kernel 宣稱十台交換機各 0 條規則」寫的（`hpp:296-315` 有 151 筆量測）。
它做對的事是：**拒絕把一份空表當成事實套用**。

然後 `:1893` 的整份取代**把同一件事用刪除又做了一次**：

| | 沒有 verdict 檢查（2026-08-07 的行為） | 有 verdict 檢查（今天） |
|---|---|---|
| 消費者問「dpid 3 有幾條規則」 | 回 `flows` 空 ⇒ **0 條** | dpid 3 **不在陣列裡** ⇒ 迴圈找不到 ⇒ **0 條** |

**兩者對每一個現有消費者是同一個答案**（§3.3 逐一驗證過：全部都是
`for sw in tables: if sw["dpid"] != n: continue`）。
⇒ **F-6 讓 `classifyFlowStatsReply` 這整套防護在端點層面等於沒接上。**
這是 [[existence-is-not-wiring]] 的形狀：**判斷寫對了、log 印對了，套用那一步沒接線。**

### 2.5 `isUp == false` 那個 skip：形狀一樣，但**不是**這條缺陷，也**不要**一起改

`:1027-1030` 在**嘗試讀取之前**就 skip 掉 down 的交換機，結果同樣是消失。但：

- 它不是「讀失敗」，是「沒讀」。把它一起 carry-forward 會讓**死掉的交換機的流表永遠活著**，
  那是 F-4／F-16 的樂觀方向，比 F-6 更難看。
- 🔴 **但它已經誤導過一個工具**：`doc/audit/2026-08-28_chaos-harness/harness/invariants.py:145-146`
  寫著 `f"dpid {dpid} is down; tables read empty by design, so nothing is decidable"`——
  harness 作者以為 down 的交換機**讀成空表**，實際上是**整台消失**。
  結論（SKIPPED）碰巧一樣，理由是錯的。

⇒ 我的修法**明確區分「沒嘗試」與「嘗試了但失敗」**，只 carry-forward 後者，並把這個區分寫進註解，
以免未來有人「順手把 isUp 那條也修一修」。

## 3. 修復設計

### 3.1 誰對：**註解對，程式碼錯**

判準是消費者需要什麼，不是哪個先寫的。

- **一份被標記的舊表**：消費者可以自己決定要不要信（路由可以拒絕改道、GUI 可以標灰、
  稽核可以計數）。**壞掉的部分是可見的。**
- **一台消失的交換機**：對每一個現有消費者都等於「這台沒有規則」，
  **而且和真的沒有規則長得一模一樣**。**壞掉的部分是不可見的。**

兩種都是不誠實，但只有第二種**沒有任何人有辦法發現**。KNOWN-ISSUES 把方向標成「靜默」是對的。

### 3.2 選定：**保留最後一份 ＋ 標記**（`stale_since`／`stale_polls`／`last_error`）

新的回應形狀（**新增欄位，陣列結構不動**）：

```json
[
  {"dpid": 1, "flows": {"0": [ … ]}},
  {"dpid": 3, "flows": {"0": [ … ]},
   "stale_since": 1756800000, "stale_polls": 4, "last_error": "suspect_timeout"}
]
```

`last_error` 是**固定字彙**，讓消費者可以 switch，不是給人讀的句子（人讀的那句已經在 log 裡）：

| token | 對應 skip path |
|---|---|
| `no_response` | `:1073` 空 body／控制平面不可達 |
| `unparseable` | `:1095` 非 JSON body |
| `reported_failure` | `:1125` proxy 回 `{"error":…}` |
| `suspect_timeout` | `:1143` 空且慢 |

**從來沒讀成功過**的交換機（開機第一輪就失敗，沒有舊表可留）：
輸出 `{"dpid": N, "flows": {}, "stale_since": …, "stale_polls": n, "last_error": …, "never_read": true}`。
**不是靜默省略。** 這一格是空的，但它**明說自己是空的以及為什麼**——
和今天「整台不見」的差別就是這一句。⚠️ 這會讓契約測試變紅，見 §6。

### 3.3 為什麼是「保留＋標記」而不是「省略＋`unreadable:[…]`」——逐個消費者

而在它們改完之前，預設答案仍然是錯的。
