# sender-gate 校準結果（PREREG-B v1.0 §3；凍結後、正式臂前）

**跑法**：`sender_gate_calibration.sh`（腳本檔，非 inline）於 nslab guest VM 內；
路徑＝veth pair＋network namespace 的 sender→sink 直連，**不經過任何受測 build 的 binary**。
用 veth 而非 `lo` 是刻意的：臂本身跑在 veth 上，用 `lo` 校準會**高估** G，
而高估正是會讓「發送端受限」偽裝成「交換機受限」的方向。

**原始三 rep（收端 Mbit/s）**：8781.8 ／ 8331.3 ／ 8693.0（loss 0 ／ 0.022% ／ 0.0003%）

## G ＝ **8331.3 Mbit/s**（取三 rep 最小值＝保守端）

## 套用凍結的判定式：`G < 5×X ⇒ rung X 及以上標 sender-limited`

⇒ 安全上界＝`G/5` = **1666.3 Mbit/s**。逐階檢查：

| rung (Mbit/s) | 5×rung | vs G | 判 |
|---|---|---|---|
| 360（註冊梯頂） | 1800 | < 8331 | ✅ 安全 |
| 540（規則延伸） | 2700 | < 8331 | ✅ 安全 |
| 810（規則延伸） | 4050 | < 8331 | ✅ 安全 |
| 1215（再一階 ×1.5） | 6075 | < 8331 | ✅ 安全 |
| **1822** | 9110 | **> 8331** | 🔴 **此階及以上標 sender-limited** |

🔑 **結論**：整條註冊梯階（到 360）**以及規則可能產生的前三個延伸階**（540／810／1215）
全部落在發送端能力的五分之一以內 ⇒ **本輪任何讀值都不會是發送端的極限**，
除非 saturation stop 一路沒發火而爬到 1822 以上（那種情況本身就要另外報）。

⚠️ **這個數字只餵判定式，不入 primary、不與任何臂的讀值並列**（PREREG-B §3 防火牆條款）。
⚠️ G 是**這顆 VM 上的**發送端能力，不轉移到機器 1。
