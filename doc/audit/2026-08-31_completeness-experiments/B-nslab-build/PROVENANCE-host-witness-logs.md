### 2a. 🔴 更正一句：**那支 sampler 不受「argv 假冒」影響——我把自己的警告套寬了**

`host_witness_sampler_RECOVERED.sh` 的檔頭寫「遠端機器測試線關於 argv 形狀 fixture 的警告
**適用於**這支 sampler」。**實測不成立**，因為它數的是 `ps -eo comm`：

```
$ bash -c 'sleep 2; :' qemu-system-x86_64 -smp 7 -m 3333 &
/proc/<pid>/comm     : bash                    ← 來自執行檔名，行程設不了
/proc/<pid>/cmdline  : bash -c sleep 2; : qemu-system-x86_64 -smp 7 …
```

⇒ **`comm` 是執行檔名，`argv[0]` 是行程自己寫的。** 用 `comm` 數的不會被那種 fixture 騙。
（`prctl(PR_SET_NAME)` 或把二進位檔改名仍可改 `comm`，所以它不是防偽的，只是**比 argv 準得多**。）

**前後對照，跑的是它那條逐字的指令**（09-01 03:1x）：

```
ps -eo comm | grep -c '^qemu-system'
  兩個 argv 冒充者啟動前 : 1
  兩個都在跑時           : 1     ← 沒有變
  結束後                 : 1
  兩者的 comm / argv[0]  : bash / qemu-system-x86_64
對照組（改用 argv 數）：ps -eo args | grep -c qemu-system → 7
```

🔑 **對照組是這一格的一半**：若不同時顯示「用 argv 數會變成 7」，
「comm 數不變」也可能只是因為那兩個行程根本沒起來。

**B 輪線用更強的 spoof 複驗過**（`da70fc6`）：`exec -a` 是**真的**改 `argv[0]`，
不像 `bash -c '…' name` 只設 `$0`（後者連 `cmdline[0]` 都還是 `bash`）：

| spoof | `comm` | `cmdline` |
|---|---|---|
| `bash -c 'sleep 4; :' qemu-system-x86_64` | `bash` | `… qemu-system-x86_64 -smp 7` |
| `bash -c 'exec -a qemu-system-x86_64 sleep 4'` | **`sleep`** | `qemu-system-x86_64 4` |

同一時刻：`comm` 數 **1**（只有真 VM）／`args` 數 **6**（兩個 spoof 全中）。

### ⚠️ 措辭要準：**exe 是「更好的欄位」，不是 comm 是「壞掉的欄位」**

`comm` **不防偽**，只是騙法不同——`prctl(PR_SET_NAME)`、寫 `/proc/self/comm`、
改二進位檔名都改得動，而且它**截在 15 bytes**。
⇒ 換成 `/proc/<pid>/exe` 的理由是 **exe 由核心維護、行程改不了**，
**不是**「comm 會被 argv 騙」。**這兩種說法會把下一個人導向不同的修法。**
