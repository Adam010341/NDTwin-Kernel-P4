# 預註冊 §E：fast build 的天花板在哪裡，它對 P4 程式敏感嗎？

**狀態：草案，寫於任何細梯階資料存在之前。** 2026-08-31 23:3x CST。
**裁決鏈**：Adam 08-31「細梯階先不做，看後面有沒有時間」＋ §C 的結果提出了一個
**原本不存在的問題**（見 §1）。**本輪不是 §D 那個被我建議不做的輪次**——差別在 §2。

## 1. 問題（來自 §C，不是來自「區間太寬」）

§C 量到：`firewall.p4` 與 `ndtwin_switch.p4` 兩支差異很大的程式，
**在 fast build（D 臂）上讀到同一階 360，且乾淨點正上方的實收速率相差 0.9%／1.6%**；
同樣兩支在 stock build（A 臂）上差 **1.57×**（70 vs 110）。

我從中推論：**在 fast build 上，P4 程式已經不是瓶頸。**
`FINDINGS-C-p4-program.md §3.2` 把那個推論標成「機制假說，不是量到的」，
理由是證據只有**兩階的實收速率**，而梯階（360→540，×1.5）粗到看不見更小的差異。

⇒ **本輪要問的是：把尺變細之後，兩支程式的 fast 臂還會落在同一點嗎？**

**這是一個關於天花板的問題，不是關於比值的問題。**

---

## 2. 🔴 為什麼這不是 §D 我建議不做的那一輪——而且是**結構上**不是

§D 反對的是「看到 `(5.14, 12.0)` 之後回頭用更細的尺重跑 ①」，
三個理由中最重的是**時序觀感**：即使預註冊，事後換尺就是補救。

**本輪只量 D 臂（fast build），兩支程式各兩支。A 臂（stock）一支都不重測。**

⇒ `R = fast / stock` 的**分母不會被本輪碰到** ⇒ **本輪在結構上不可能收窄 R**。
這不是一句承諾，是一個可以被檢查的設計性質：
**沒有新的 A 臂資料，就沒有新的 R。**

🔴 **本輪的任何數字都不得用來更新 ①／R-B2／R-B3 的任何區間。** 若之後有人想那樣用，
必須開一輪自己的、含 A 臂的設計，並自行承擔 §D 的觀感問題。

## 3. 設計

| 項 | 值 |
|---|---|
| 平面 | 機器 2（nslab guest），與 B／§C **同一顆 VM、同一組 binary**，沿用其 sha256 身分紀錄 |
| 臂 | **D×ndtwin ×2、D×firewall ×2**（四臂）。交錯序＝`Dn1 Df1 Dn2 Df2`，每臂 fabric 全重啟 |
| 梯階 | **360 380 400 420 440 460 480 500 520 540**（20 Mbit 等距，覆蓋 B／§C 讀值所在的那一個粗階 `[360, 540)`） |
| 其餘 | clean ≤0.5% on 3-rep medians、STEP_S、payload 1400 B、sender gate、F1/F2/F3 **全部沿 B 輪逐字** |
| 讀出 | 每臂最高乾淨階 |

⚠️ **等距而非幾何**：這一段只跨 1.5×，幾何梯階在這個範圍內沒有意義。
**等距是為了讓「兩支程式落在同一點」這個判斷有均勻的解析度**，不是為了好看。

## 4. 註冊結果（兩向都可發表，不利的那向寫在前）

令 `X_n` ＝ D×ndtwin 兩臂的最高乾淨階，`X_f` ＝ D×firewall 兩臂的。

| 判定 | 條件 | 敘述 |
|---|---|---|
| 🔴 **程式仍然可分辨** | 兩組**嚴格分離**（`min` 一組 > `max` 另一組） | fast build **仍然對 P4 程式敏感**，只是 B／§C 的粗梯階看不見 ⇒ **§C 的機制推論（「程式不再是瓶頸」）被否證，必須撤回**。`FINDINGS-C-p4-program.md §3` 整節要改寫。**這對我們不利——那一節是這一輪唯一有新意的部分。照報。** |
| **不可分辨** | 兩組不嚴格分離 | 在 20 Mbit 解析度下兩支程式的 fast 臂落在同一點 ⇒ §C 的推論**在這個解析度上撐得住**（**仍不等於「瓶頸是 I/O」**——見 §5） |
| **不可判定** | 任一臂 NO_MEASUREMENT ≥2 階、或 sender gate 發火、或 F1/F2/F3 任一失敗 | 照實報不可判定，**不得挑可用的臂作結論** |

⚠️ **門檻是「嚴格分離」，與 B 輪的 R-B1a 同構，不是新發明的判準。**

## 5. 🔴 這一輪即使全綠也**不會**證明的事

**「fast build 的瓶頸是封包 I/O 路徑」不是本輪能回答的問題。**
本輪只能說「fast 臂的讀值對**這兩支程式**不敏感」。
要指認瓶頸在哪一層，需要**換 I/O 路徑而不換程式**的實驗（例如 veth vs 別的傳輸），
**那一輪沒有設計、沒有排程、也不在本輪的宣稱範圍內。**

「不敏感」與「瓶頸在 X」之間差一個未做的實驗，兩者不可互相代入。
