# 開機環：機制定案、兩個修法、與一個不再需要靶的驗證方式

2026-08-25，`8/25 mainDev`。審查員 `8/24 auditer`（全程逐項對抗性驗證）。
預註冊：`PREREG.md`（A）、`PREREG-B.md`（B）。原始資料在 `raw/`。

## 1. 結論（可引用的措辭）

環是 **`switches` 與 `IntelligentRyu` 兩個事件迴圈之間的 2-cycle**，
由 `EventSwitchEnter` handler 底下的**無時限 request-reply** 閉合。**已觀察，非推論**。

| | 環（佇列飽和） | twin 收斂 | 不變量 | wall |
|---|---|---|---|---|
| **Phase 0** 無修法 | **2/3** | 1/3 | 違反 | 413/411/54s |
| **Phase 2** 修法 A（時限） | **0/3** | **3/3** | 仍會違反 | 167/54/54s |
| **Phase 3** 修法 B（搬離迴圈） | **0/3** | **3/3** | **成立（159 stack / 0 違反）** | 59/56/59s |

⚠️ **三個階段都是 N=3、同一次機器開機**。收斂率之間**不可直接比較**（見 §5）。

## 2. 機制（三條腿互相獨立、同一答案）

1. **greenlet dump 的 frames**：IR 的 `_event_loop` 停在 `get_switch`／`get_link` → `reply_q.get()`
   （`app_manager.py:279`，無逾時）；`switches` 的 `_event_loop` 停在
   `lldp_packet_in_handler` → `_events_sem.acquire()`（`app_manager.py:302`）。
2. **佇列普查**（本輪新增儀器 `e27283a`）：`IntelligentRyu` 128/128 balance **−12**、
   `switches` 128/128 balance **−43/−18**、其餘四個 app 0/128。**兩邊同時飽和**——
   我原本只推論了 IR 那一半。
3. **log 計數器**：由碼序導出的規則（P1/P2）在 47 份歷史 log 上 P1 47/47、P2 零違反，
   且**逐格指認的卡點與 dump 的 frame 一對一吻合**。

四類參與者全數指認：**10 條 OF 連線 greenlet ＋ `switches` 兩條迴圈**塞 IR 的佇列；
**REST handler（`get_switch`×22 ＋ `get_link`×21 ＝ 43）**塞 `switches` 的佇列；IR 自己停在無時限站點。

**環的可見後果**＝餓死 kernel 的拓撲輪詢：wedge 的開機只服務 4 次
`GET /v1.0/topology/switches`，恢復的服務 26 次。**kernel 失明 148 秒**（修法 A）
或**永久失明**（無修法）。

## 3. 三個站點與兩個修法的關係

`get_topology_data` 底下有三個無時限 request-reply，依碼序：

| # | 呼叫 | 誰處理了它 |
|---|---|---|
| 1 | `get_switch` | **本輪修法 A**（`cce9c5d`） |
| 2 | `get_link` | **本輪修法 A**——但**從未實跑過**（見 §4） |
| 3 | `get_all_host` | `d1d973d`（08-24） |

**先前「已知修法用盡」的判斷是反的**：`d1d973d` 只處理了第三個；`72fbae6`（async）的 spawn
在 `:851`，**在 #1/#2 之後**，構不到它們。**修法 B 一次消除全部三個**（整個 body 離開事件迴圈）。

## 4. 明確**不**宣稱的事

1. **N=3 是暗示不是結論**。若真實環率仍為 2/3，P(0/3) ≈ 3.7%。
2. 只宣稱「**#1/#2 是當前的環邊**」，不宣稱「環不可能再形成」。
3. 🔴 **`get_link` 的時限從未執行過**（全部 log 零筆）。它是有根據的保險——Phase 0 boot1
   正是卡在 `get_link`——但**其執行期行為與保真度代價均未觀察**。
4. 🔴 **佔用源普查未做**。本輪沒有任何一格說明「誰把 128 格填滿」。
5. **B 不取代 A**：搬到 worker 的呼叫仍可能卡，而**卡住的 worker ＝ 無聲停更**，
   比 wedge 更難發現。A 的時限是 B 的安全網，`_topology_*` heartbeat 是它的偵測器。
6. **不宣稱任何開機秒數**（8/27 deck 規則）。

## 5. 🔬 觀察者效應（審查員指出，影響第 3 欄的讀法）

B 臂每 6 秒送一次 SIGUSR2，每次走一遍 greenlet heap。
對**不變量（主判準）無害**——結構性質不因取樣改變；
但對**收斂率（次判準）是新變因**。⇒ **B 臂的收斂率與 Phase 0/2 不是同一個量。**

## 6. 為什麼 B 的驗證方式比結果本身重要

先前每一輪都要**靶活著**才能測，而靶在同一次機器開機內從 4/4 掉到 1/4
（17.48h→**4/4**、18.43h→**1/4**、~19h→2/4、20.09h→**2/3**）。Phase 0 花 21 分鐘只為確認靶還存在。

B 的主證據是**結構性斷言**：

> 任何 dump 中，`_event_loop` 的 frames 永不得含 `get_switch`／`get_link`／`get_all_host`／`send_request`。

**冷機器上也能驗。** 受控結果：B 的 dump **159 stack / 0 違反**；修法前對照 **12 stack / 4 違反**。
