### 2.1 遙測來源（telemetry source）——一個字、三個讀者
- 值域 `auto | none | cooperative | link`。語意：`cooperative`＝今天的路（pipeline clone 到 CPU port、proxy 合成 sFlow）；`link`＝B（交換機側 veth 上 `tc … action sample`，root 的 emitter 合成 sFlow）；`none`＝不取樣（E 的對照組）；`auto`＝**逐台**：`pipeline_is_ndtwin(dpid)` ⇒ `cooperative`，否則 ⇒ `link`。
- **knob 檔 `p4_proxy/mininet/telemetry_override`**：同 `host_count_override` 的形狀（第一個非空非 `#` 行；不存在＝`auto`；值不在值域＝拒絕啟動）。**寫入者只有 `ndt`（D）**：`ndt up p4 [N | --app <dir>] [--telemetry <word>]`——沒給 `--telemetry` 就寫 package 宣告的 `telemetry.source`（沒 package 或沒宣告＝`auto`）；`ndt down` 不動它；`ndt status` 印 `telemetry  <word>  (p4_proxy/mininet/telemetry_override)`＋解析後每台的來源；`stack.sh` 的 `START_BG_IDENTITY` 加 `telemetry=<word>`。
- **package.json v1 加選配 top-level `"telemetry": {"source": "<word>"}`**（B 的 loader 接受並存到 `Package.telemetry_source: str = "auto"`；C 的 preflight 驗值域）。`format` 仍 1（加法）。
- **解析函式 `app_package.telemetry_source(package, dpid, knob_path=None) -> "none"|"cooperative"|"link"`（B 實作）**：knob 有值且非 auto ⇒ 該值；否則 package 宣告且非 auto ⇒ 該值；否則 auto 規則。**C 在 `main.py` 用同一規則自算 `_telemetry_source(package, dpid)`，兩邊併回後 orchestrator 收成一個**（同 P2 `pipeline_is_ndtwin` 的作法）。

- **kernel（A）對 `inputPort == 0 && outputPort != 0` 的樣本：只存 `m_egressCounterReports[(agent, outputPort)]`，不存 `m_counterReports`**（今天那個死分支會把它算成反向邊）。`creditHostBoundEgressEdges` 照舊只付 host-bound。gtest 要證：egress-only 樣本 ⇒ switch→host 邊有量、host→switch 邊為 0；ingress 樣本 ⇒ 反之；兩者相加＝今天一個「雙埠」樣本的效果。
- **kernel（A）對每個格式正確的 flow sample 先記鏈路位元組、再談流身份**：`m_counterReports`／egress 銀行的累加移到 etherType 判斷**之前**（兩個分支 `:1266`／`:1327` 都是）；非 IPv4 不再 `continue` 掉整個樣本。這就是「鏈路使用率與程式無關」的機制（PLAN §8.3 第一條）。IPv4 樣本的一切數值結果逐位元組同今天。

### 2.3 L3 觀測（A）：`FlowKey` 三個家族、IPv4 口徑不變
- 家族：`IPv4`（今天的欄位、今天的 JSON 鍵、今天的雜湊與排序**對 IPv4 鍵值完全相同**）、`IPv6`（外層或**第一個找得到的** IPv6 五元組：src/dst 16 B、next header、L4 port；擴展標頭鏈至少跳過 hop-by-hop／routing／fragment 三種，其餘當不透明 ⇒ 退 L2）、`L2`（`src_mac`、`dst_mac`、`ethertype`；自訂標頭 0x1234／0x1212／0x812 全落這裡）。VLAN（0x8100）剝一層再判。
- **`ihl`**：IPv4 的 L4 位移由 `ihl*4` 算，`ihl==5` 時算出的位移＝今天的常數（所以既有流量結果不變）；`ihl<5` 當畸形（計數、不記流）。mri 的 option 包（ihl>5）要有 fixture 證明 port 讀對。
- 結構：不改既有欄位的型別與名字；加 `family`（enum）、`ethType`、`srcMac/dstMac`（uint64）、`srcIp6/dstIp6`（`std::array<uint8_t,16>`）；`operator==` default；`operator<`／`FlowKeyHash` 對 IPv4 鍵的行為不變（新欄位在 IPv4 家族恆為零，所以可以直接納入比較與雜湊——但 gtest 要證 IPv4 鍵的 hash 值與今天相同：用今天的算式算一次當期望）。
- JSON（`getFlowInfoJson`）：IPv4 家族**鍵與值逐字同今天**，外加 `"family": "ipv4"`；IPv6 家族 `src_ip6/dst_ip6`（字串）；L2 家族 `src_mac/dst_mac`（字串）＋`ethertype`（十六進位字串）。`:3111` classifier 分派只對 IPv4 家族做，其餘跳過（不是錯誤：那些流沒有 P4 五元組規則可下）。
- 計數與揭露：`GET /ndt/get_sflow_stats` 加 `samples_by_family {ipv4, ipv6, l2}`、`malformed_ipv4_ihl`（不是 warning log，是可讀的數字）。
- **契約測試不動**：`test_GoldenFixture.cpp`／`test_SFlowEmitterRoundtrip.cpp` 與既有 `emitted_*.bin` 一個位元組不改，且仍綠。新增 fixtures（A 經 `generate_emitted_fixtures.py` 新增條目，`test_sflow_emitter.py::CommittedFixtureTest` 自動涵蓋）：`emitted_ipv6_udp.bin`、`emitted_arp.bin`（已有，改用它驗 L2）、`emitted_custom_0x1234.bin`、`emitted_ipv4_ihl6_tcp.bin`、`emitted_vlan_ipv4.bin`、`emitted_egress_only.bin`（inputPort 0）。新 gtest `tests/test_FlowKeyFamilies.cpp` 逐個餵進 parser 斷言家族、鍵值、鏈路位元組是否被記、`get_sflow_stats` 的計數。
