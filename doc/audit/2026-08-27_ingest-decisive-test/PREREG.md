## 0. 要答的問題

工單 P 的少報，是**封包沒進到 bmv2 的管線**（介面與 bmv2 socket 之間掉了），
還是**進了管線但遙測沒報**？

## 1. 儀器：為什麼是那兩個 direct counter

`ndtwin_switch.p4`：

| 位置 | counter | 型別 |
|---|---|---|
| `:285` `flow_5tuple_counter` | 掛在 `flow_5tuple`（`:346`） | **direct** |
| `:286` `ipv4_lpm_counter` | 掛在 `ipv4_lpm`（`:362`） | **direct** |
| `:425` `egress_port_counter` | 按 egress port | indexed（**本測試不用**） |

🔑 **兩張表互斥，所以「相加」是對的**（`:390-393`）：

```p4
if (hdr.ipv4.isValid()) {
    if (!flow_5tuple.apply().hit) {
        ipv4_lpm.apply();
    }
}
```

⇒ 一個封包**最多命中其中一張**，`sum` 不會重複計。

📌 **順帶更正一個先前記下的疑慮**：先前擔心「clone 可能重複計」。
`clone_preserving_field_list` 在**表 apply 之後**（`:410`）產生的是 **egress** 複本，
**不會重跑 ingress 的表** ⇒ **direct counter 不受 clone 影響**。
那個疑慮對 `egress_port_counter` 成立，對本測試用的兩個**不成立**。

## 1-bis. 🔴 這個和不是「進入管線的封包數」——它排除了四類

| 排除的 | 為什麼 | 位置 |
|---|---|---|
| `packet_out`（控制器注入） | 在任何表之前 `return` | `:383-387` |
| **LLDP** | 直接呼叫 `send_to_cpu()` 動作，**不經表** | `:394-396` |
| **ARP／其他非 IPv4** | 走 `l2_forward`，**那張表沒有 direct counter** | `:397-398`、`:366` |
| **IPv4 但兩張表都 miss** | direct counter 只在**命中表項**時遞增 | — |

⇒ **這個和是「進入管線並被 IPv4 表命中的封包數」，是真值的下界，不是真值。**
**任何把它當成「進入管線的封包數」的句子都是錯的**，包括我自己等一下要寫的結論。

---

## 2. 🔴 比值兩邊不同母體——這是本測試最容易死的地方

| | 數什麼 |
|---|---|
| 分子 `Σ direct` | **該交換機所有 ingress port** 的、**被 IPv4 表命中**的封包 |
| 分母 veth RX | **單一介面**的、**所有** frame（含 ARP、LLDP、miss） |

**兩個都要修正，否則比值在零丟包時也不會是 1：**

1. **分母改成「該交換機全部 `sN-eth*` 介面 RX 的總和」**，與 direct counter 的範圍對齊。
2. **工作點必須讓 IPv4 壓倒背景**。⇒ **不可以用「完全安靜」當校準點**：
   安靜時 veth RX 幾乎只有 LLDP，而 LLDP 不進分子 ⇒ **比值趨近 0，看起來像 100% 丟包。**
   ⇒ 「安靜臂」定義為**低速率但非零的 IPv4 流**（下方 Q 臂）。

🔑 這條直接來自 [[ratio-sides-must-share-a-population]]：**問「這兩欄的定義一樣嗎」。**
本例的答案是**不一樣，而且有兩個維度不一樣（範圍與封包種類）**。

## 3. 儀器三問（**在押任何一個臂之前跑，第 1 問沒過就整個作廢**）

| # | 問題 | 做法 | 通過條件 |
|---|---|---|---|
| 1 | **讀得到嗎** | `read_table_entries()`，看每個 entry 的 `counters` | **每一個 entry 都是 dict，不得有 `None`** |
| 2 | **會動嗎** | 灌流量，前後兩次讀 | 單調遞增 |
| 3 | 🔴 **它數的是我以為的東西嗎** | **餵已知輸入**：`ping -c 100` 單向 | Δ 落在 **[100, 110]**（ARP/重傳容差） |

🔴 **第 1 問有一個具體的已知陷阱，而且程式碼裡已經寫著**
（`p4_client.py:571-576`）：P4Runtime **只在目標願意時**填 `counter_data`，
沒填時該 entry 的 `counters` 是 **`None`**，而註解明說
「a zero here is therefore not proof of an idle rule, only of a rule whose counter was not reported」。

⇒ **註冊：任何一個 entry 的 `counters is None` ⇒ 該次讀取整體作廢，
不得把 `None` 當 0 加進總和。** 要分開回報 `n_entries` 與 `n_counters_present`。
**這正是今晚 `read_egress_counter` 那個缺陷的同族，只是這次它在讀取路徑上。**

📌 第 3 問是這裡最有價值的一問：**它把「儀器對不對」變成一個有已知答案的算術題**，
而不是「數字看起來合理嗎」——後者今天已經被證明零保護力。

## 5. 🔴 判讀表（**跑之前寫死**）

令 `R = Σ direct(Δ) / Σ veth_RX(Δ)`，同一交換機、同一視窗。

| Q 臂 | L 臂 | 結論 |
|---|---|---|
| `R_Q ∈ [0.90, 1.10]` | `R_L ≤ 0.80` | ✅ **封包沒進管線**——丟在介面與 bmv2 之間。工單 P 的少報有資料面成因 |
| `R_Q ∈ [0.90, 1.10]` | `R_L ∈ [0.90, 1.10]` | ✅ **封包都進了管線** ⇒ 少報在**遙測側**，不在資料面 |
| `R_Q < 0.90` | 任何 | 🔴 **VOID**——校準點就對不上，代表母體修正沒做對（見 §2），**不得解讀 L** |
| `R_Q > 1.10` | 任何 | 🔴 **VOID**——分子大於分母在物理上不可能 ⇒ 範圍或視窗對錯了 |
| 其他 | 其他 | 🔴 **以上皆非**：照實回報，不硬塞進前兩列 |

**我的預測（寫死）**：`R_Q ≈ 0.95`、`R_L ≈ 0.65`（審查員先前提過 0.65 這個數）。
🔴 **信心：對 `R_Q` 高，對 `R_L` 低。** 若 `R_L` 落在 0.80–0.90 這個帶，
**兩列都不成立 ⇒ 走「以上皆非」，不要四捨五入到 ≤0.80。**

## 5-bis. 下界性質怎麼限制結論（**不可略過**）

`Σ direct` 是下界 ⇒ **`R` 系統性偏低**。因此：

- **`R_L ≤ 0.80` 只有在 `R_Q` 落在 [0.90, 1.10] 時才有意義**——
  校準臂證明了偏低的量在該工作點是小的。
- **不可以拿 `R` 的絕對值去估「丟了幾 %」。** 能宣稱的只有
  **「L 相對 Q 掉了多少」**，而且要寫成相對量。
- 🔴 **反向的失敗模式**：若 L 臂的**背景比例**比 Q 臂高（例如更多 ARP／更多 miss），
  `R_L` 會單純因為母體組成而下降 ⇒ **看起來像丟包**。
  ⇒ **必須同時回報 `Σ veth_RX` 與 `Σ direct` 的絕對值，不能只給比值。**

## 6. 明確不宣稱

1. **不裁定丟包的確切位置**——只分「表命中之前」與「之後」。

3. **不跨世代沿用**任何數字。
4. 本測試**不回答**「①是不是 bmv2 特有」。
