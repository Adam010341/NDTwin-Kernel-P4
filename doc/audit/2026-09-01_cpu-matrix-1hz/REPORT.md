## 頭條

**kernel 的 CPU 在五個取樣率上一致低了 46.3 點，而每樣本的邊際成本沒變。**

| 取樣率 | 1 kHz（08-20） | 1 Hz（09-01） | 差 |
|---|---|---|---|
| 1/1024 | 49.1% | 2.9% | −46.2 |
| 1/512 | 50.4% | 3.9% | −46.5 |
| 1/256 | 51.1% | 5.3% | −45.9 |
| 1/128 | 53.9% | 7.7% | −46.3 |
| 1/64 | 60.1% | 13.5% | −46.6 |

（poll-off 臂＝拿掉儀器輪詢之後的純 ingest 成本。單位是**一顆核心**的百分比，機器有 14 顆。）

- **散布 0.68 點**，噪聲地板約 0.7 ⇒ 五個取樣率上是**同一個常數**，不隨取樣率放大。
  這是 `PREREG.md` §3-2 在資料存在之前寫死的形狀。
- **斜率不變**：1/1024 → 1/64 之間，1 kHz 漲 11.0 點，1 Hz 漲 10.6 點。
  **被拿掉的是固定成本，不是每樣本成本。**

## 對照——沒有動的東西

| | 1 kHz | 1 Hz |
|---|---|---|
| iperf3（每格工作相同，噪聲基準） | 113.9–114.8% | 113.1–114.3% |
| bmv2 | 151.6–158.6% | 142.3–158.3% |
| proxy | 6.7 → 25.0% | 6.2 → 24.7% |
| **儀器成本**（poll-on − poll-off） | 6.3–8.0 | 7.1–7.7 |

**只有 kernel 掉下來。** 若是機器、探針或行程歸類變了，iperf3 與 bmv2 會一起動。
儀器成本兩輪都是 7 點上下，也沒動——那是 harness 的性質，不是 kernel 內圈的性質。

**守衛通過**：兩輪 iperf3 封包數**完全相同**（5,357,127），`/proc/net/dev` 總 tx 差 0.3–0.4%。

## 🔴 本輪沒有取得 1 Hz 的零點

三個 `mzero` 複本**全部作廢**：每一格的成對 poll 臂都帶著約 2,378 個非零 twin 讀數，
是 1/64 那格的複本，不是零點。

**成因**：`NDTWIN_CLONE_DISABLE=1` **全 repo 沒有任何讀者**——
`p4_proxy/proxy_agent/main.py:77` 自己把它列為「這個 repo 最常重複的 bug 形狀」的實例，
`doc/audit/2026-08-31_sampling-ceiling-after-merge/lib_e.sh:773` 也記過。
08-20 那輪已經為同一件事發過撤回（它的 `mnone` 格），而我**用同一個旗標去做 `mzero`，
掉進同一個洞**。

📌 08-20 最後拿到的那個有效零點，關鍵不在機制而在**順序**：它是
「**先驗證控制成立、才開始量**」（32 條邊零非零讀數，同時 205.9 Mbit/s 在流）。
我是**先量完才檢查**。那就是控制組與標籤的差別。

⇒ **1 Hz 那一欄不能拆成 baseline ＋ ingest**，所以圖上沒有 08-20 那種堆疊分解。
每個取樣率的**差值**不需要零點（同一取樣率相減，baseline 若兩輪相同就會消掉——
而「是否相同」本身未驗證，這正是不畫那個拆解的理由）。

## 🔴 08-20 那支 analyser 有一個會無聲說謊的函式

`analyse_matrix.py:total_sample_rate()` 用 **`gcd(所有非零 twin 讀數)`** 回推取樣量子。
前提是 twin 回報「整數個樣本」：

| | 相異非零讀數 | gcd | |
|---|---|---|---|
| 08-20 | 24 | 11,812,864 | ✅ 量子化，回推有效 |
| 09-01 | 559 | **1** | ❌ 沒有量子化，回推無效 |

gcd 塌成 1 之後它**直接回傳原始總和**：`414,898,073` samples/s，真值約 35，**差 1.2 千萬倍**。
不丟例外、不警告、不回 `None`。這是 [failures-that-report-success] 的形狀，
而**同一個呼叫就在 08-20 自己那條頭條擬合裡**（`206 µs/sample`）。

**對 08-20 的資料它是對的**——那一輪的讀數確實量子化。但它是個地雷，
下一個換了資料形狀還照用它的人會拿到一個長得像量測的數字。

⇒ 本輪守衛改用**不需要量子**的統計（iperf3 封包數＋`/proc/net/dev` 總 tx）。
kernel CPU 來自 `/proc/<pid>/stat`，從頭到尾不碰 twin，不受影響。

（量子化為什麼消失——很可能是 ticket Q 那個除數改動的痕跡——**本輪沒有追**。）

## 對帳：這個數字跟 08-20 解釋不了的那塊一樣大

08-20 報告的結論是：`556 樣本/s 時 57.2 點的 ingest 成本裡，46.3 點在 34.7 樣本/s 就已經付掉了`
——一塊「形狀不明的固定成分」，也正是那張圖判定「這條線給不出飽和點、
不要引用任何從斜率算出的取樣率天花板」的理由。

**本輪量到的位移是 46.3 點。** 兩個數字一樣。

⚠️ **這是巧合等級的吻合，不是歸屬。** 08-20 那輪的 kernel 比現在舊十二天，中間至少夾著
ticket Q 的 in-loop 除數儀器與今天的 B-2①／E-2。Adam 2026-09-01 裁示接受這個混淆、
不另建「只差一個常數」的 binary。**所以本輪的差值是「兩輪之間的差」，不是「這個改動的效果」。**

同型警告見 [arithmetic-that-fits-is-not-the-mechanism]：方向與量級都對得上，
仍然什麼都還沒證明。

## 下一步（給 Adam 裁）

1. 🔑 **配對 A/B 現在明顯值得做。** 從今天的 HEAD 只把 `kFlowPathRecomputeInterval`
   改回 `microseconds(1000)` 重建，兩顆 binary 同場交錯量。有了「46.3 點、五個取樣率上恆定、
   而且剛好等於前一輪解釋不了的那塊」這個很具體的標的，歸屬才有意義。
   收在 baseline ＋ 2–3 個取樣率即可，不必五個。
2. **零點要重做，而且要先驗證再量。** 需要一個真的會移除 clone 的機制——
   `NDTWIN_CLONE_DISABLE` 不是。08-20 的撤回文字說明了正確路徑是
   `DELETE → INSERT → settle`，而且**必須重啟 fabric**，不只重啟 proxy。
3. **`total_sample_rate()` 應該在 gcd 塌成 1 時拒絕回答**，而不是回傳總和。
   那是三行的事，但它現在活在一條被引用過的頭條裡。
4. **08-20 那個「206 µs/sample」的斜率**：本輪沒有推翻它（1 Hz 那一輪的斜率也接近），
   但也沒有重算——沒有 samples/s 就擬合不了。要更新那張圖得先解決第 3 點。
