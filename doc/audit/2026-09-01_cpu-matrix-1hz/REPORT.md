## 頭條

**那 46 點是一個階梯，不是一個常數——它在零取樣時不存在。**

| 取樣率 | 1 kHz（08-20） | 1 Hz（09-01） | 差 |
|---|---|---|---|
| **none（零取樣）** | **2.9%**（n=3） | **1.9%**（n=3） | **−1.0** |
| 1/1024 | 49.1% | 2.9% | −46.2 |
| 1/512 | 50.4% | 3.9% | −46.5 |
| 1/256 | 51.1% | 5.3% | −45.9 |
| 1/128 | 53.9% | 7.7% | −46.3 |
| 1/64 | 60.1% | 13.5% | −46.6 |

（poll-off 臂＝拿掉儀器輪詢之後的純 ingest 成本。單位是**一顆核心**的百分比，機器有 14 顆。）

- **零取樣時兩輪只差 1.0 點；一旦開始取樣就差 46.3 點。**
- 有取樣的五格散布 0.68 點、噪聲地板約 0.7 ⇒ 在**有取樣的範圍內**是同一個常數
  （`PREREG.md` §3-2 事前寫死的形狀，在它涵蓋的範圍內成立）。
- **斜率不變**：1/1024 → 1/64，1 kHz 漲 11.0 點、1 Hz 漲 10.6 點。

### 🔄 更正：先前把它讀成「固定成本」，零取樣那一格推翻了那個讀法

零點還沒量到時，本檔與對 Adam 的口頭回報都寫「**被拿掉的是固定成本，不是每樣本成本**」。
在有取樣的五格裡那句話是對的，**但外推到零就錯**：1 kHz 的 kernel 在零取樣時只用 2.9%，
和 1 Hz 的 1.9% 幾乎一樣。

⇒ 正確的形狀是：**1 kHz 的成本在「有沒有樣本進來」之間跳一階（2.9 → 49.1），
然後幾乎不隨取樣率成長；1 Hz 沒有那一階。**

📌 這一階**就落在 08-20 自己標為「從沒量過」的那段區間**（0 → 34.7 樣本/s）。
那一輪寫得很清楚：「固定成分在 34.7 樣本/s 以下的形狀不明」。**不明的那段就是全部的答案。**
教訓照 [[verify-the-purpose-not-the-mechanism]] 的形狀：五個點都落在階梯的同一側時，
它們對「階梯在哪」零鑑別力——而那正是要問的事。

### 🔑 而且 1 Hz 這一輪的擬合**打得到自己的零點**

用 08-20 的 samples/s（守衛已證兩輪流量相同）對五格 poll-off 做最小平方：

| | 擬合截距 | 實測零點 | 差 |
|---|---|---|---|
| 1 kHz | 48.48% | 2.89% | **+45.59**（65× 噪聲地板） |
| **1 Hz** | **2.33%** | **1.89%** | **+0.44**（在 0.7 噪聲地板之內） |

斜率：**205.6 → 199.7 µs/sample**（差約 3%，每樣本成本實質未變）。

⇒ 08-20 因為「線外推到零會差 46 點」而撤回所有從斜率算出的取樣率天花板；
**對 1 Hz 這顆 kernel，那個理由不再成立**——線通過它自己的實測零點。

⚠️ **只解決了往下外推。** 往上仍然不能外推：08-31 的 E 輪量到 1/64 以上成本轉為超線性
（1/64 → 1/8 是 ×2.23），所以拿 `(100 − 1.89) / 19.97 × 1000 ≈ 4,900 樣本/s` 當容量
**仍然是錯的**，只是錯的理由從「線打不到零」換成「線在量測範圍以上會彎」。

## 零點是**第二輪**補的，第一次做錯了

第一次的三個 `mzero` 複本**全部作廢**，補做的六格在 `zero_cell.sh` 裡，標籤 `mzs_*`。

**補做的機制**：clone 的判斷式是
`random(meta.sample_rand, (bit<16>)0, SAMPLE_RATE - 1); if (meta.sample_rand == 0)`。
沒有任何 `SAMPLE_RATE` 值能讓機率變 0（設 0 會讓上界下溢成 65535，仍然 1/65536）
⇒ 把亂數的**下界從 0 改成 1**，`== 0` 永遠不成立，clone 永不觸發。一個 token、
沒有死碼、不動 proxy，轉發與 counter 全部照舊。`trap` 綁 EXIT/INT/TERM 還原，
結束時 log 印出判斷式與 `SAMPLE_RATE = 256`。

**沒有採用的兩條**：刪 mirror session（08-20 撤回文寫明 DELETE 打在空的 P4Runtime 帳本上
是 no-op，target 的 PRE group 變孤兒繼續 clone）；補上 `NDTWIN_CLONE_DISABLE` 的 reader
（為了量測改產品碼，順序不對）。

🔑 **控制在開量之前驗，不是量完再驗**（`verify_zero.py`）。三個複本各自：
**24 次 twin 輪詢全讀 0 bps，同時交換機介面移動 1.89 GB**。
兩個斷言都是必要的——只有「twin 讀到零」的話，沒有流量、iperf 掛掉、kernel 不回應
都會滿足它，而那些都不是待測條件。

## 🔴 第一次的零點為什麼全廢

三個 `mzero` 複本**全部作廢**：每一格的成對 poll 臂都帶著約 2,378 個非零 twin 讀數，
是 1/64 那格的複本，不是零點。

**成因**：`NDTWIN_CLONE_DISABLE=1` **全 repo 沒有任何讀者**——
`p4_proxy/proxy_agent/main.py:77` 自己把它列為「這個 repo 最常重複的 bug 形狀」的實例，
`doc/audit/2026-08-31_sampling-ceiling-after-merge/lib_e.sh:773` 也記過。
08-20 那輪已經為同一件事發過撤回（它的 `mnone` 格），而我**用同一個旗標去做 `mzero`，
掉進同一個洞**。

📌 08-20 最後拿到的那個有效零點，關鍵不在機制而在**順序**：它是
「**先驗證控制成立、才開始量**」（32 條邊零非零讀數，同時 205.9 Mbit/s 在流）。
我是**先量完才檢查**。那就是控制組與標籤的差別。

⇒ 第一次因此沒有零點；`mzs_*` 那六格補上了它，見上一節。
**作廢的六格保留在 audit-raw**——它們是「這個標籤是錯的」的證據本身。

## 🔴 08-20 那支 analyser 有一個會無聲說謊的函式

`analyse_matrix.py:total_sample_rate()` 用 **`gcd(所有非零 twin 讀數)`** 回推取樣量子。
前提是 twin 回報「整數個樣本」：

| | 相異非零讀數 | gcd | |
|---|---|---|---|
| 08-20 | 24 | 11,812,864 | ✅ 量子化，回推有效 |
| 09-01 | 559 | **1** | ❌ 沒有量子化，回推無效 |

gcd 塌成 1 之後它**直接回傳原始總和**：`414,898,073` samples/s，真值約 35，**差 1.2 千萬倍**。
不丟例外、不警告、不回 `None`。這是 [failures-that-report-success] 的形狀，
而**同一個呼叫就在 08-20 自己那條頭條擬合裡**（`206 µs/sample`）。

**對 08-20 的資料它是對的**——那一輪的讀數確實量子化。但它是個地雷，
下一個換了資料形狀還照用它的人會拿到一個長得像量測的數字。

⇒ 本輪守衛改用**不需要量子**的統計（iperf3 封包數＋`/proc/net/dev` 總 tx）。
kernel CPU 來自 `/proc/<pid>/stat`，從頭到尾不碰 twin，不受影響。

（量子化為什麼消失——很可能是 ticket Q 那個除數改動的痕跡——**本輪沒有追**。）

## 對帳：這個數字跟 08-20 解釋不了的那塊一樣大

08-20 報告的結論是：`556 樣本/s 時 57.2 點的 ingest 成本裡，46.3 點在 34.7 樣本/s 就已經付掉了`
——一塊「形狀不明的固定成分」，也正是那張圖判定「這條線給不出飽和點、
不要引用任何從斜率算出的取樣率天花板」的理由。

**本輪量到的位移是 46.3 點。** 兩個數字一樣。

⚠️ **這是巧合等級的吻合，不是歸屬。** 08-20 那輪的 kernel 比現在舊十二天，中間至少夾著
ticket Q 的 in-loop 除數儀器與今天的 B-2①／E-2。Adam 2026-09-01 裁示接受這個混淆、
不另建「只差一個常數」的 binary。**所以本輪的差值是「兩輪之間的差」，不是「這個改動的效果」。**

同型警告見 [arithmetic-that-fits-is-not-the-mechanism]：方向與量級都對得上，
仍然什麼都還沒證明。

1. 🔑 **配對 A/B 現在更值得做，而且問題變得更尖。** 從今天的 HEAD 只把
   `kFlowPathRecomputeInterval` 改回 `microseconds(1000)` 重建，兩顆 binary 同場交錯量。
   要問的已經不是「省了多少」而是**「那一階為什麼會被『有沒有樣本』觸發」**——
   零取樣時 1 kHz 幾乎不花錢，代表那個迴圈的成本條件在流表是不是空的，不在它醒幾次。
   **只要 baseline ＋ 一個低取樣率就分得出來**，不必五個。
2. 🔑 **那一階落在 0 → 34.7 樣本/s 之間，而那段從來沒有人量過。**
   本輪也只是把它的兩端釘住，中間仍然空白。要知道它是階梯還是陡坡，
   得在 1/1024 以下再加兩三格（1/4096、1/16384）。**這是現在最便宜也最有資訊的一輪。**
3. **`total_sample_rate()` 應該在 gcd 塌成 1 時拒絕回答**，而不是回傳總和。
   那是三行的事，但它現在活在一條被引用過的頭條裡。
4. **`page_matrix-decomposition.png`（08-20 那張）該更新或加註。** 它畫的
   「48.5% 截距 vs 2.89% 實測零點、相距 45.6 點」對 1 kHz 仍然正確，
   但讀者會把它當成這個 kernel 現在的樣子。1 Hz 的截距是 2.33%、零點 1.89%。
