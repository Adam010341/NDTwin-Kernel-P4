# scripts-p4req — what each file is (worker REQ, TICKET-p4proxy-requirements)

[Co-developed with claude code -- Adam]

Checksums: `SHA256SUMS` (end of round 1), `SHA256SUMS.r2` (round 2). `scripts_sha256.p4req-851cefd7.log`
shows round 1's file still verifying for every script round 2 did not change.

| file | round | what it is |
|---|---|---|
| `run_suites.sh` | r2 = v3 | both suites (+ empty-HOME variant) under one interpreter, through guarded_build.sh; line 1 = HEAD + venv + realpath |
| `run_suites.v2.sh` | r1 (end) | the text the round-1 logs after the pip-freeze fix were written by (v1, before that fix, was not kept; it differed in 2 lines: `$(dirname PY)/pip freeze` instead of `python -m pip freeze`) |
| `compare_verbose.sh` | r2 = v3 | per-test verdict diff of two interpreters; saves the WHOLE diff to `<suite>_verdictdiff_<A>_vs_<B>.p4req-<sha>.log`; adds the empty-HOME suite |
| `compare_verbose.v2.sh` | r1 | missing verdict file = RED; printed the diff only |
| `compare_verbose.v1.sh` | r1 | the defective first version (silent "0" when a suite did not load) |
| `verdicts.py` | r1 | runs a unittest suite and writes test id -> verdict |
| `check_pins_vs_venv.py` | r1 | each pin line of a requirements file vs a `pip freeze` (cannot see a MISSING line) |
| `check_imports_vs_requirements.py` | r2 | every third-party import of p4_proxy/ and tools/p4_exercise/ vs the file (sees MISSING lines) |
| `evidence_r2.sh` | r2 | writes the round-2 evidence logs (fingerprint, pip check, build hashes, pip index, resolution, whole diffs, check_pins, check_imports) |
| `regen_p4runtime_pb2.py` | r1 | ⚠️ the EXPERIMENT (route C, venv-pb5regen) -- NOT the candidate's tool. The candidate's is `p4_proxy/regen_p4runtime_pb2.py` in commit 7cc50b42 (sha256 66fb47b0…); venv-cand was regenerated by its uncommitted predecessor (d7efa3f4…) |
| `regen_mutant.py` | r1 | the mutant of the candidate's (uncommitted) tool used in `regen_tool_red_green.p4req-55cebe6c-wt.log` |
