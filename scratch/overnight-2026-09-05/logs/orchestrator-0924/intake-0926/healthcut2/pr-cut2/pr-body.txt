Adds the second part of the P4 health check: the lab run. A run can drive bring-up A (packet level, on a Mininet fabric) and bring-up B (an external P4Runtime controller), read the results back, and decide each cell of the verdict table, also offline from a saved run. A lab run pins one commit, refuses a dirty probe tree, runs the code it froze into the run directory, and ends INCOMPLETE with a reason when a stop signal, an exception or an unclean teardown cuts a round short.

It has not been run against a live lab yet. Every path is covered by the unit tests and by the mutation gate in tests/shell/mutate_p4_health.sh.

It also lets the health probe's controller name the tutorials port base in tests/python/test_grpc_port_block.py, which was the one failure in trunk's CI.
