## 10-line summary (Traditional Chinese)

1. API 形狀照 tutorials：ternary `[value, mask]`、range `[low, high]`、optional 一個值，`priority` 放頂層；不寫的欄位就是 don't-care，EXACT 欄位不能不寫。
2. 驗證都在 stub.Write 之前回 400：要 priority 的表沒帶或帶 0、default entry 帶 priority、`value&~mask≠0`、low>high、用遮罩 0／整段 range／lpm /0 表示 don't-care。依據是 libpifeproto 裡 PI 前端的錯誤字串【觀測】，字串在不代表一定會觸發。
3. priority 型別是 int32【觀測】。bmv2 內部會反轉，而且有 BM_MAX_PRIORITY 上限，值不知道【推論】⇒ Cut A0 先用拋棄式 bmv2 實測。「數字大的贏」是轉述 spec，碼裡註解也這麼寫。
4. 身分＝(dpid, table, priority 若該表有 priority 欄, 正規化後的 match bytes)，沿用 rule_install_times.entry_key。modify／delete 一定要帶 priority，也不能改 priority。
5. 開機 entry：pre-flight 和 writer 共用新的 match_shape.py，G5 解除；apply_package_entries 不用改，開機 entry 不進 journal（每次都從 package 檔重算）。
6. Journal 只記 API 寫入，存在 `.run/table_entry_journal.jsonl`，紀錄帶 p4info sha。順序是先寫交換機、fsync 之後才回 200；每台交換機一把鎖，讓 journal 的順序等於交換機上實際的順序。
7. 重放在 startup 套完 package entries 之後、以及 readopt 時跑：先依身分折疊成淨效果，sha 不符就不套用，套完寫 snapshot；重放的寫入不再追加，這就是 replace-vs-add 的防線。external 不重放，journal 一個 byte 都不動。

## Questions for Adam (each has a recommended option and consequences in DESIGN.md §8)

- **Q1** When a fresh `ndt up` happens, what happens to the journal?
  - Recommended: (a) `ndt up` quarantines it at the step that starts bmv2. This is quarantine's first call site, and it needs one shell change.
  - (b) Use the bmv2 pid from the switch manifest. No shell change, but power-cycle and readopt then need their own handling.
  - (c) No scoping. Not recommended: yesterday's operator rules would be written into today's new fabric.
- **Q2** Can the generic writer write tables NDTwin owns?
  - Recommended: (a) no. Every table on a baseline switch, and any table bound owner ndtwin, answers 409 `owned_by_ndtwin`. This extends Adam's ruling 8-1 to the runtime API.
  - Cost of (a): a POST into baseline `ipv4_lpm` answers 200 today and would answer 409.
  - (b) Block only `flow_5tuple`, which this cut newly makes writable.
  - (c) Allow all, disclose only.
- **Q3** How to treat the second spelling of don't-care (mask 0, full range, lpm /0)?
  - Recommended: (a) 400 with "omit the field". int-v1's hand-written port mask 0x0000 entries would have to drop those fields.
  - (b) Normalise to omission and disclose it in the response.
- **Q4** What does the response say when the journal write fails (disk full)?
  - Recommended: (a) 200 with `journaled:false`, a note, and a failure count.
  - (b) Roll the write back and answer 507.
- **Q5** Should multicast/PRE API writes be journaled too?
  - Recommended: (a) not in this cut; keep api_routes.py:1130's not-journaled note.
