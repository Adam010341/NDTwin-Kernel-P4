Adam 要去睡了,實驗室整晚歸你。今晚的產出不是「做了很多事」,是**天亮時他手上多幾個他自己不會發現的 bug**,而且機器還是乾淨的。

這個 skill 有一個貫穿全場的前提:**沒有人可以問。** 標準流程裡「停下來問使用者」的那一格今晚是空的——停下來等於整晚空轉。所以每一步都要有「問不到的時候怎麼辦」的替代路徑,而不是把問題丟著。

---

## 第 0 步:先把 `/goal` 那一行印給他,然後才開工

**你打不出 `/goal`。** 它是 Claude Code 內建的 local command,不是 skill、也沒有對應的 tool——只有 Adam 本人在輸入框打得出來。它會裝一個 session-scoped 的 Stop hook,在條件成立之前不讓這個 session 停。

沒有那個 hook,整晚只要有任何一輪自然結束,session 就停了,實驗室空轉到天亮。**這是今晚唯一一個「不做就全盤皆輸」的動作,所以排在最前面,在他還沒離開的時候。**

第一件事:輸出一行給他複製,格式長這樣(條件照今晚實際範圍改寫):

```
/goal 修完今晚範圍內的問題,並完成整機測試、把結果寫進 WAKEUP.md
```

寫條件的規矩:

- **短、可判定。** hook 要拿它判斷「成立了沒有」。整段 prompt 貼進去會讓它判不準——playbook 留在這個 skill 裡,goal 只放終點。
- **終點要包含交付,不只包含工作。** 只寫「修完問題」的話,測試跑到一半它就可能認為成立了。
- 印完就接著做下一步,**不要停下來問他貼了沒有**——他正要走,你問了他也只會回一個「好」。

⚠️ 天亮以後 hook 會自己清掉,**不要叫他去打 `/goal clear`**。那是提早取消用的。

🔴 **貼的時機是「這個 session 最後一次 compact／行程重啟之後」,不是開場貼一次就算數。** hook 是 session-scoped 的,行程換了就沒了,而整晚必定會被 compact 好幾次。開場貼、半夜重啟、剩下的時間裸奔到天亮——這是最容易發生、也最難察覺的失敗:session 看起來一切正常,只是再也不會被擋著不停。

同一條規則管住所有「派出去就不管」的東西:**background agent 隨行程死。** 09-06 凌晨的慣例員就是這樣沒的,重派之後才做完。所以:

- 行程重啟後第一件事是**點名**:哪些 background 工作還活著、哪些沒了。沒了的重派,**不要當成做完了**。
- 每一件 background 工作都要能從帳本重派(誰、做什麼、做到哪)。第五步「一輪記一次帳」就是為了這一刻。
- 需要它自己不停的,`/goal` 要跟著重貼——那一行印給他的時候順便說一句「重啟後再貼一次」。

## 第 0.5 步:走之前該問的,一次問完

他人還在,這是今晚唯一能問的視窗。用互動表單(建議放第一、寫後果、末留自由輸入)。

**只問猜錯代價高的**,其餘全部自己決定:

- 今晚範圍的界線在哪——「剩下的問題」具體指哪一份清單/哪些 issue
- 有沒有**不准碰**的東西(某個正在跑的長實驗、某份還沒對帳的 raw、某個分支)
- 明早要什麼形式的交付

問完就封口。之後所有問題累積到 WAKEUP.md,不要再叫醒他。

## 第一步:把剩下的問題修完

沿用 `keep-working` 的分界:方向要問、步驟自己決定;小問題記下來累積著,不逐項回報。

**但今晚有一條改寫:「立刻停下來問」在無人可問的情況下,變成「寫進 WAKEUP.md、選一條合理的路繼續走」。** 撞到方向級的問題不是停下來睡覺,是把「我遇到什麼、我選了哪條、為什麼、翻盤成本多少」寫清楚,然後走下去。翻盤成本高到不該由你決定的——那才是真的停,而且要停在一個乾淨的狀態(改動 commit 掉或 stash 掉,不要留半套)。

**唯一不能自己決定的還是那些**:送對外訊息、花錢、不可逆的刪除或覆蓋、動共用/正式環境。這條 `/goal` 跟本 skill 都不放寬。

⚠️ **測試沒看過紅就不算修完**(專案守則的 mutation gate)。每一個「我修好了」後面要有一個「我讓它壞過、測試有抓到」。今晚沒人幫你 review,這是唯一擋得住「修了個寂寞」的東西。

## 第 0 輪:回歸格(偵察 agent 在讀碼的同時跑,不要等)

**上一晚「紅過、已修好」的發現都在 `tools/test_workflow/live_cells/` 裡變成了格**(cell＝一個
可重現的動作序列＋一個預期判定)。進入規則是**紅過就永不退出**,所以這個目錄只會長大,而
「紅了幾格」就是唯一該單調的數字。

派偵察 agent 之後**立刻**跑它,不要等他們回話——它們是並行的,而且這一輪要花的是實驗室的時間:

```bash
# 完全不碰實驗室的那些,先跑(別人還握著 claim 也能跑)
tools/test_workflow/live_cells/run_cells.sh --requires none
# 要實驗室的那些,claim 之後
NDT_ROOT=/home/adam/Desktop/NDTwin-Kernel tools/test_workflow/live_cells/run_cells.sh
```

最後一行是 `CELLS: <pass>/<total> pass, <fail> FAIL, <skip> SKIP`,格與格之間它自己還原
(orphans → down → clean → orphans;還原沒過它就停,不會把上一格的殘骸算進下一格)。

- **翻紅＝🔴 置頂 + 當晚必修 + 寫進 WAKEUP.md 第一段。** 一格紅代表「一個已經修好的缺陷回來了」,
  那比今晚新找到的任何東西都優先——它會讓今晚其他每一個觀測都變得不可信。
- **SKIP 不是 PASS。** 格自己說了為什麼(前提沒建起來、fabric 沒起來),照它說的讀。
- **PASS 不代表那條修法被驗過**:格只驗它自己那一句。`CELLS.md` 的「What these cells do NOT
  cover」列著缺口,派測試計畫之前讀它一次。
- 併入任何動到 `ndt`／kernel／proxy 的修法之後,**再跑一次相關子集**(`--tag ndt`／`kernel`／
  `proxy`)。這一晚自己的修法也算。
- 今晚新找到又修好的缺陷,天亮前**加一格**:`CELLS.md` 一列、`tests/fixtures/live_cells/<name>/old/`
  放今晚的原始 log、`tests/shell/mutate_live_cells.sh` 加兩顆變異(delete 與 widen)。
  沒有 `old/` 的紅就沒有格——**這跟第一步的 mutation gate 是同一條規矩。**

## 第二步:先叫外部 agent 偵察,再動實驗室

**順序不能顛倒。** 你剛剛花了幾小時修 bug,你的 context 現在被「我剛修過的地方」佔滿——你想得到的測試會全部繞著你剛碰過的檔案打轉。外部 agent 唯一的價值就在於**它沒有你的先入之見**,所以它必須在你派測試計畫之前先講話。

開法(獨立 session,不是 subagent——context 完全乾淨):

```bash
claude --bg --model opus --add-dir /home/adam/Desktop/NDTwin-Kernel "<角色 prompt>"
```

`claude agents` 列得到、`claude logs <id>` 讀得到、`claude stop <id>` 收得掉。長跑照專案守則包 `setsid`。

給偵察 agent 的 prompt 要包含:

1. **一個角色**(見第三步),不要給「請找 bug」這種無視角的指令——無視角的 agent 只會把 README 重講一遍
2. **明講它不准動實驗室**:不 claim、不 `ndt up`、不 `ndt down`、純讀 code 與文件
3. **要它交三樣東西,不是一份 bug 清單**:
   - **假說**:「我認為 X 在 Y 條件下會壞」——要具體到可以被證偽
   - **觀察**:要看什麼才能證明或推翻它(哪個指令的哪個欄位、哪份 log)
   - **派誰去測**:它建議用什麼角色、什麼動作序列去打這個假說

第三樣最重要。偵察 agent 的產出是**測試計畫的原料**,不是結論。

**另外派一個只做一件事的偵察 agent:翻歷史,找 bug 的形狀。**
`git log`、`CHANGELOG.md`、過去的 fix commit——不是為了看修了什麼,是為了看**同一類錯誤反覆出現在哪裡**。
一個專案修過三次的地方會有第四次;修法愈是「加一個檢查擋住這個 case」而不是「讓這個 case 不可能發生」,復發率愈高。
要它交:**復發形狀的清單**(這一類 bug 長什麼樣、出現過幾次、每次的修法是加擋板還是改結構),以及**哪些擋板今晚值得去繞過看看**。

⚠️ 收回來的假說**不要照單全收**。外部 agent 沒跑過任何東西,它的假說是從讀 code 猜的,錯誤率很高。你的工作是把它們按「證偽成本」排序:一個指令就能推翻的先做掉,要開整套 fabric 才驗得了的排進第四步的隊伍。

## 第三步:想清楚視角,再派人去測

這一步是整個 skill 的核心。**列一堆角色沒有用,要先知道什麼叫「好的視角」。**

### 為什麼視角比測試案例重要

bug 不住在功能裡,住在**假設的交界**。作者寫每一行的時候心裡都有一組沒有寫下來的假設,而那些假設彼此之間從來沒有被一起想過。一個好的視角 = **一組作者沒有一起想過的假設**。

所以派角色的判準不是「這個角色像不像真人」,是「這個角色會不會踩到一組沒被同時考慮過的假設」。

### Adam 自己的體感清單(當先驗,不當結論)

他點名這五個情境最容易出事:**kernel 與 tool 不停重開**、**併發(tool 同時動作)**、**高流量(量測本身會出問題)**、**路由規則更動**、**拓撲檔修改**。

⚠️ **這是先驗,不是待辦。** 它的用法是把偵察與測試的預算往這五塊傾斜,**不是**照著跑一遍就交差。
兩件事要同時做:(a) 這五塊要有人去打;(b) **他沒點到的地方也要有人去**——一份體感清單能列出來的,通常是他已經踩過、因此已經有防護的;真正會咬人的在他沒想到的那一塊。
如果一整晚的發現全部落在這五項之內,那不是驗證了他的直覺,是**你的測試只走了他指的路**。

### 生成視角的四條軸

給軸而不是給清單,因為軸可以再生——今晚跑完你還能自己長出新的角色。

**1. 時間軸——作者假設事情照順序發生。**
同時做、反過來做、做到一半斷掉、第一步跟第二步隔很久。
NDTwin 的具體面:兩個 owner 同時 `ndt claim`;`ndt down` 撞上別人正在跑的 measurement;claim 過期的那一秒剛好有 app 在寫 fabric。

**2. 規模軸——作者在 4 host 上寫,在 128 host 上跑。**
邊界值(0 / 1 / max / max+1)、數量級跳躍、同一個動作重複一萬次。
NDTwin 的具體面:`ndt up 4` 跟 `ndt up p4 128` 之間來回;`NDT_TOPO=` 硬塞一個 host count 對不上的拓撲;路由規則每秒更新一次連續打一小時,看 telemetry 的 double-count tripwire(`ndt check`)會不會漂。
⚠️ 專案文件宣稱「4-host-model-against-a-128-host-fabric 這個錯誤不可能因為忘了設環境變數而發生」。**那句話是一個可以被證偽的宣稱,今晚去打它。** 文件裡寫得最有信心的那一句,通常就是測得最少的那一條路徑。

**3. 狀態軸——作者假設從乾淨開始。**
從上一個實驗的殘骸開始、pidfile 說沒有但 port 被佔、claim 說空的但 fabric 有人在用。
NDTwin 的具體面:`ndt apps orphans` 存在這個指令本身就說明這個 bug 發生過;`.test_run/pids/` 是共用的,`ndt down` 會殺掉登記在裡面的所有人——**誰登記進去、誰忘了登記,是狀態軸最肥的一塊。**

**4. 意圖軸——作者假設使用者想做「對的」事。**
使用者想做的是一件**完全合理、但作者沒設想過**的事。這條軸最難自動生成,也最容易找到真 bug,因為它跳出了測試套件的想像力。
NDTwin 的具體面:一個趕論文的人想用 NDTwin 做一個它不是為此設計的實驗,於是改 `testbed_topo.py`、中途改 host count、只想要一張圖。

### 今晚的角色牌組

每個角色**綁一條軸 + 一個具體動作面**。派出去的 prompt 要寫死角色動機,不要寫「請測試 X」——動機才會生出你想不到的動作序列。

| 角色 | 軸 | 他會做什麼 |
|---|---|---|
| 趕論文的研究生 | 意圖 | 改自己的拓撲塞進 `NDT_TOPO=`,中途改 host count,只在乎能不能出圖,不讀 README |
| 換手的接班人 | 狀態 | 從別人留下的殘骸開始,看到 claim 沒過期照樣 `ndt down --deep`,不知道 `.test_run/pids/` 是共用的 |
| 流量壓力狂 | 規模 | `ndt up ovs 128` 打到 OOM,路由規則不停更新,專找 `ndt check` 誤報或漏報 |
| 併發雙開 | 時間 | 兩個 owner、同一個 reader 起兩次、`ndt down` 故意撞 measurement |
| 重開循環壓力測 | 時間×狀態 | `ndt up` / `ndt down` 連續循環幾十次不休息,每一輪之間**不清乾淨**,看第幾輪開始出現殘骸累積、pidfile 漂移、port 沒放掉。Adam 把這條排在體感第一位 |
| 對帳審計員(**R7,常設**) | 跨軸 | 完全不製造流量,只讀 `ndt status --check` 與 audit-raw,專找**兩邊狀態不一致**——claim 說空的但 fabric 有人用。見下 |

### R7 對帳審計員:每次夜巡必派,而且跟其他角色**並行**

其他角色是輪流上場的,R7 不是。它**每次夜巡都要派,而且從頭開到尾**,跟當時在跑的角色同時存在。

- **唯讀,沒有例外。** 不 `ndt up`／`down`／`clean`／`claim`／`release`／`apps start|stop`,不製造流量,不裝規則,不動 `.test_run/`,不改追蹤檔,不殺行程。它不持 claim,因此不佔第四步的隊伍——**這就是它能跟別人並行的原因**。
- **10 分鐘一輪**,每輪記一列:claim／bridges／:8000／:8080／pidfiles／netem／誰在用／我自己跑了什麼。最後一欄是給別人對帳用的:別人看到的異常要能對得上 R7 的動作。
- **規模角色(R4 那種)在跑的時候切被動讀**:不跑 `ndt apps orphans`、不帶 `--check`、不打 kernel 端點,只看 `ovs-vsctl list-br`／`ss`／`ps`／檔案。理由是量測期間任何多餘的請求都會進到別人的數字裡。
- **回合之間用背景 sleep 撐**(背景跑一支 `sleep 600`,回來再開下一輪),不要靠「我等一下再看」的記憶,也不要前景空轉——前景等會被工具逾時砍掉。

**為什麼值得一個常設名額**:09-05 那一晚 R7 交出 4 條不一致(I-1…I-4),而其中三條是在**沒有任何角色在看的時段**露出來的——`ndt down` 之後的間隙、R3→R6 交班的 6 分 20 秒空窗、以及一段「有人在 128 host 上灌流量但沒有任何介面說得出是誰」。角色本人在那些時刻要嘛已經收工、要嘛還沒開工。**空窗是唯一沒有主人的時段,而狀態不一致就住在那裡。**(`scratch/overnight-2026-09-05/rounds/03-R7-reconciler.md`)

⚠️ **這個角色的招牌陷阱是自證**:它的儀器會把「沒有」量成「有」,或反過來,而兩種都長得像發現。09-05 一晚踩了三次,三次都是同一條:

| 錯在哪 | 差點寫成什麼 | 正解 |
|---|---|---|
| `curl … \| tr ',' '\n' \| wc -l` 數 Ryu 的 dpid ⇒ 印 9 | 「Ryu 說 9、OVS 說 10」的**假不一致** | 讀 JSON 逐字(`[10,3,8,1,6,2,7,9,5,4]` ＝ 10);`tr` 的輸出沒有結尾換行,`wc -l` 少算一個 |
| `grep 'Controller.cpp:100' kernel.log` ⇒ 0 命中 | 「那行 warning 不存在」 | kernel.log 的**色碼夾在 token 中間**(`[[94mController.cpp[0m:[95m100[0m`)⇒ 先去色碼,或改用不含跳脫字元的片段 |
| 掃 `NDT-TEST-FIXTURE`,唯一命中是自己那支 `awk`(樣式就寫在自己的 argv 裡,而管線裡的 awk 是**另一個 pgid**,排除自己 pgid 沒排到它) | 「出現了 fixture 假陽性」 | 樣式在執行時拼起來(`awk -v a="NDT-TEST" '$0 ~ (a "-FIXTURE")'`),或只比對 `comm` 欄位 |

⇒ **先驗證儀器看得見一個已知存在的東西,再相信它回報的 0。** 任何「用 grep 找字串」的檢查,只要目標字串會出現在你自己剛留下的痕跡裡(命令列、逐字稿、剛寫的筆記),就會撈到自己:要嘛比對結構化欄位,要嘛顯式排除自己(連自己管線裡的子行程一起)。詳見 `~/.claude/skills/before-sleep/SKILL.md`。

角色不夠就照四條軸再長。**每派一個新角色,先講得出它踩的是哪兩個假設的交界**——講不出來的角色不要派,那是在浪費實驗室時間。

## 第四步:實驗室只有一個,序列化

**硬規則:任何時刻只有一個 agent 動 fabric。**

由你(orchestrator)持 claim 並排隊,不要讓五個 agent 各自去 `ndt claim` 賽跑——claim 檔是 `.test_run/lab.claim`,它擋不住同時寫。

每一輪的形狀:

1. **claim** — `ndt claim <分鐘> "<角色名>"`,`NDT_OWNER` 一定要帶(專案守則)
2. **記下基線** — `ndt status` 的輸出存檔。還原要跟這個比,不是跟你的印象比
3. **交棒** — 把該角色的 prompt 發出去,明講它的時間預算與「不准做什麼」
4. **收工** — 拿回結果
5. **還原並驗證**(見下)
6. 過了才輪下一位

### 還原的驗證(這一步不能省)

Adam 今晚給的授權是:**可以跑實驗、可以改設定檔,但每一輪必須能還原、而且要驗證還原成功。**

`ndt down` 跑完**不等於**還原了。三個都要過——而且有一步在 `ndt down` **之前**:

- 🆕 **`ndt down` 之前先跑一次 `orphans_verdict.sh`**(09-11 裁)。網路那半只有 `:8000` 開著的時候
  問得到:`ndt down` 關掉 kernel 之後,那半就永遠只剩 `NOT CHECKED (kernel down)`,於是「這一輪
  有沒有留下規則或鎖」這個問題**在每一輪都只能在事後被回答成「沒人問」**。
  ```bash
  NDT_OWNER=... tools/test_workflow/ndt apps orphans > predown.txt 2>&1; orc=$?
  bash tools/test_workflow/orphans_verdict.sh predown.txt "$orc"
  ```
  `run_cells.sh` 的還原已經是這個順序,照著抄。
- `ndt clean` — exit 0(它就是那條 teardown assertion)
- `ndt apps orphans` — **看輸出、不看 exit code**(09-10 更正:合併樹上 rc 5「processes clean、residue could NOT be checked」在乾淨 OVS4 是**常態**——sim 的 window is LOST;P4 起著 sim 會回 rc 2——root 行程的 `/proc/<pid>/fd` 讀不到,351c;兩個都不是「有 orphan」)。判「還原了」要三件同時成立:processes 那半沒有 untracked process 在跑、tally 的 `dated rule(s) in a window` 為 0、`lock(s) held` 為 0;`question(s) not answerable`／`could not be dated` 只是 NOTE。**`fix/orphans-rc-read-tally` 併進 trunk 之後直接用 `tools/test_workflow/orphans_verdict.sh`(印 `VERDICT: CLEAN` 才算過)**;併進去之前用上面三件手判。🆕 **09-11 加一個地板**:上面「三件同時成立」只有在**網路那半至少答了一句**時才算過(`lock <t> free`／`HELD`／`no flow entry arrived during that window`／`rule(s) listed:`)。**kernel 開著、tally 有印、而三個 lock probe 全 `NOT CHECKED (http 500)` ⇒ helper 印 `VERDICT: NOT CHECKED`、rc 3**——那三個 0 是計數器沒被加過,不是量到 0(F-OFFLINE-1 §1.11;`ndt` 自己對同一份觀測回 5)。**`grep -F 'VERDICT: CLEAN'` 在那格現在不會 match ⇒ 照舊「沒過就不准派下一位」**,補救是修好 probe 再問一次。部分盲照舊 CLEAN＋NOTE;`ndt down` 之後照舊 `CLEAN -- the process half only`(Adam 09-10)。
- `ndt status --check` — 🆕 **不是「exit 0」**(09-11 裁,SMALL-ISSUES 42)。`ndt down` 清掉
  `up.target`,所以收工那一刻 `--check` 的正常答案是 **rc 3＝「沒查」**(沒有基線可比),
  閒置的實驗室也是 rc 3。要求 exit 0 會讓這一件永遠不過、於是永遠被忽略。
  正確的判準是:**`down` 之後的 `--check` 輸出跟閒置基線逐字相同**——所以第 2 步那份基線
  (`ndt status --check` 的全文,含 rc)要存檔,收工時 `diff` 它。逐字差異只該剩下必然的那幾行
  (claim 剩餘時間、note、`up.target` 被清掉的時間戳);多出任何一行都是這一輪留下的東西。

任何一條沒過:

- **這一輪的所有結果標記為「環境不可信」**,不要拿去寫報告當發現
- **不准派下一位**。先修環境。髒環境跑出來的下一輪結果會讓明早的你分不清是 bug 還是殘骸
- 修不好 → 停在這裡,寫進 WAKEUP.md,`ndt release`,不要硬幹

### 修儀器也要看紅

夜巡途中一定會順手修東西:claim 的 note、`arm_down` 的措辭、還原腳本、`ndt status` 的某一句散文。**這些修法沒有閘門守著,而它們改的正是「別人據以行動的那句話」。**

09-05 的實例,一條修法生出一條更糟的缺陷:R7 報了 I-2(交班空窗裡 `lab.claim` 的 `note` 還指著已經收工的角色),修法把 note 改寫成 `lab free`——但 `ndt up` 不會改寫 note,於是 17:21 那一段,實驗室一邊在 128 host 上灌 32 條流,一邊宣告自己是空的(I-4)。**方向從保守翻成不保守**:修法前那句話讓人多等,修法後那句話讓人 `ndt down --deep`,殺掉跑到一半的量測。

它被抓到的唯一原因是**修法之後又量了同一個東西**。所以:

- 改完儀器/腳本/宣告文字,**回頭跑同一組觀測至少一次**,不要用「改小小的」當跳過的理由。
- 驗收的問句不是「這句話對不對」,是「**讀到這句話的人會做什麼動作**」——保守變不保守就是這樣看出來的。
- 這跟第一步的 mutation gate 是同一條規矩:**沒看過它說錯之前,不知道它會不會說謊。**
- 修法引入的新缺陷比原缺陷難發現,因為沒有人在找它。修法要寫進帳本,標成「新事」。

### 雷區

- 🔴 **永不 `pkill -f` / `pgrep -f`**(專案守則)。斷鏈路用 `tc netem`,不用 `ifconfig down`。
- 🔴 **`ndt down --deep` 會殺掉不是這個 stack 起的行程**——那正是它危險的地方。只有在你已經確認佔住 :8000/:8080/:8081 的東西是**上一輪自己留下的**時候才用。不確定就用不帶 `--deep` 的,讓它報出來,你自己判斷。
- 🔴 **踩到不可逆的東西就停**(會刪掉別人的 raw、會動到共用 worktree 裡別人未提交的修改、會 push 出去)。寫進 WAKEUP.md,不要自己決定。
- 🔴 **共用 worktree commit 列到檔案,不要給目錄**(專案守則)。目錄 pathspec 會把別人未提交的修改一起帶走。

## 第五步:一輪記一次帳,不要留到最後

**整晚會被 compact 好幾次。** 記在 context 裡的東西天亮就沒了,而且你不會知道自己忘了什麼。

每一輪結束**立刻**寫進 `scratch/overnight-<YYYY-MM-DD>/`:角色、動作序列、觀察、還原驗證的三個 exit code、結論。raw 照專案守則進 audit-raw。

task list(`TaskCreate`/`TaskUpdate`)隨進度更新——**那是 Adam 唯一看得到各 session 在幹嘛的地方**,不是給你自己看的備忘。

## 第六步:天亮的交付

一份 `WAKEUP.md`,放在他一眼看得到的地方。四段,順序不要換:

1. **實驗室現在的狀態**(放第一,因為這是他起床可能要立刻處理的):claim 釋放了沒、有沒有東西還在跑、機器乾不乾淨
2. **修完了什麼**——每一項後面附「哪個測試看過紅」
2b. 🆕 **回歸集的結果,一行**:`CELLS: <pass>/<total> pass, <fail> FAIL, <skip> SKIP`,後面接
   **紅格數對上一次是多少**(上升＝有修法回歸了,那要升到第 1 段;下降＝有格被修回來了,寫是哪一格)。
   翻紅的格名逐字列出來。這一行是他唯一能一眼看出「昨天修好的東西今天還好不好」的地方。
3. **找到的 bug,照「能不能重現」排序,不是照嚴重度**。重現不了的放最後並註明試了幾次——一個穩定重現的小 bug 對他的價值遠高於一個看過一次的大 bug
4. **累積的問題一次問完**,用互動表單:建議放第一、寫後果、末留自由輸入

⚠️ **「跑過」跟「讀過未執行」永不混表**(專案守則)。外部偵察 agent 的假說是「讀過」,實測結果才是「跑過」——這兩批在報告裡要分開,混在一起明早的對帳就毀了。

⚠️ benchmark 數字必指認 binary(sha + 識別碼),並跟舊結果對帳(推翻/更新/可比對哪個)。
