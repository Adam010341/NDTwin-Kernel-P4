# ndt serve 使用手冊

這份手冊說明 ndt serve 的網頁怎麼用。HTTP API 的完整參考在英文的 `tools/ndt_serve/README.md`；這裡只講頁面。

## 1. 這是什麼

ndt serve 是一個在你自己電腦上跑的小伺服器，把 `ndt` 的 lab 指令（status、claim、release、up、down、apps，以及 live_cells 驗證格）包成一個網頁和一組 HTTP API。

- **只在本機**：它只聽 `127.0.0.1`，同一個網路上的其他電腦連不到它。
- **只給你一個人用**：啟動時用 `--owner` 指定你是誰，之後每一次 `ndt` 呼叫都帶 `NDT_OWNER=<owner>`。
- **不碰網路**：頁面不從外面載入任何東西（沒有 CDN、沒有網路字型），瀏覽器的內容安全政策（CSP）只允許同一個來源。唯一往外的是「開啟 Web-GUI」，它在新分頁打開另一個 app。
- **頁面不自己做決定**：它把 `ndt` 的輸出原文照登，只依伺服器算好的欄位決定按鈕能不能按；真正擋住寫入的是伺服器和 `ndt`。

## 2. 啟動與打開頁面

```
ndt serve --owner adam
```

它會印出：聽在哪個位址、驅動哪一個 `ndt`（連同它的 sha256）、token 檔在哪裡，以及頁面的**一次性網址**，長得像 `http://127.0.0.1:8765/#k=...`。stdout 不是終端機時，網址改寫進一個權限 0600 的檔案，並印出檔名。

- `#k=` 後面是一把**一次性的 key**，不是 token。頁面打開後的第一件事，就是把它從網址列清掉，再拿它向伺服器換 token。token 只放在頁面的記憶體裡。
- 一把 key 只能用一次，10 分鐘內有效（`--nonce-ttl`）。
- **重新整理頁面就會結束 session。** 要再進來，執行：

```
ndt serve url
```

它會向正在跑的伺服器要一個新的一次性網址並印出來。

上方列的 session 狀態會告訴你目前的情況：

| 顯示 | 意思 | 怎麼辦 |
|---|---|---|
| session 已開啟 | 一切正常 | — |
| 這個網址沒有一次性 key | 網址裡沒有 `#k=`，例如重新整理過 | 執行 `ndt serve url`，打開它印的網址 |
| 一次性 key 被拒絕 | key 用過了、過期了，或不是這個伺服器發的 | 同上 |

其他常用的啟動選項：`--port`（預設 8765）、`--webgui-url`（「開啟 Web-GUI」的網址，見第 12 節）。

## 3. 畫面導覽

**上方列**，從左到右：

- 標題與 owner；
- session 狀態；
- 自動更新狀態：平常是「每 10 秒自動更新」，暫停時是「已暫停（量測中）」或「已暫停（頁面在背景）」（第 9 節）；
- 上次讀取的時間；
- 「立即更新」：馬上讀一次，暫停時也能按；
- 「開啟 Web-GUI」：在新分頁打開 Web-GUI（第 12 節）；
- 「使用手冊」：在新分頁打開這份手冊。

**五個分頁**：

| 分頁 | 內容 | 自動更新 |
|---|---|---|
| 實驗室 | lab 現在的狀態：claim、measuring、declared | 是 |
| 操作 | claim／release、up／down | 不需要（每個寫入都經過確認視窗） |
| Apps | app 的 start／stop，以及 `ndt apps status` | 是 |
| 工作紀錄 | job 清單，和 job 的 log | 清單是；log 另有規則（第 7 節） |
| 驗證格 | live_cells 的格子、逐步驗證 | 否 |

每個分頁最上面都有一行說明，告訴你這一頁是做什麼的。

### 短 id

job、逐步驗證和讀取紀錄的 id 都很長，頁面只顯示**短 id**：

- 完整的 job id 長這樣：`20260927T062127Z-a8a334`，也就是 UTC 的日期與時間，加上 6 個亂數字元。逐步驗證的 id 前面多一個 `g`，讀取紀錄的 id 前面多一個 `r`。
- 短 id 是 **id 裡的「時分」加上最後 6 碼**：上面那個 id 顯示成 `0621·a8a334`。
- 為什麼不直接取前 8 碼：前 8 碼是日期（`20260927`），同一天的每一個 id 都一樣，分不出來。
- 時分是 id 本身記的 **UTC 時間，不是台灣時間**（台灣時間 = UTC + 8，所以 `0621` 是台灣時間 14:21）。這樣短 id 的每一個字都能在完整 id 裡找到，拿去對 log 或檔名不會對錯。
- 不是這種格式的 id，顯示它的前 8 個字。
- **滑鼠停在短 id 上**，會顯示完整的 id；**點一下**，就把完整 id 複製到剪貼簿，旁邊出現「已複製」，1.5 秒後消失。

## 4. 實驗室分頁：claim、measuring、declared 三列怎麼讀

這三列都是 `ndt status` 輸出裡那一列的**原文**，頁面不改一個字。旁邊的標記是伺服器的判讀。

- **claim**：誰佔著 lab、還剩多久。旁邊的「是你的／不是你的」由伺服器判斷：只有 `ndt` 自己印的「你的 claim」格式——`yours -- <n>m left (until HH:MM:SS)`——整行吻合才算是你的。
  - 限制：如果有人的 owner 名字剛好就叫 `yours`，`ndt` 印出來的樣子和你自己的一樣，分不出來。
- **measuring**：有沒有量測在跑。只有剛好是 `nothing` 才算沒有；不是 `nothing` 時以橘色標示，而且：
  - 自動更新會暫停（第 9 節）；
  - 所有寫入都要打字確認（第 5 節）。
- **declared**：只有在 claim 宣告了 `measuring=` 時才會出現這一列。出現時的效果和 measuring 不是 `nothing` 一樣。
- **槽位**：伺服器同一時間只跑一個寫入 job。這裡顯示是空著，還是被哪一個 job 佔用。
- **讀取**：這一次讀取的時間、`ndt status` 的 rc 與 rc_class、花了幾秒，以及讀取紀錄的短 id（伺服器把 `ndt` 的原始輸出逐位元組留著）。
- **ndt status 全文**：展開可以看整份報告。
- **ndt_drift 警告**：`ndt` 在伺服器啟動之後被改過時會出現。伺服器仍然執行啟動時的那一份；要用新的，請重新啟動 ndt serve。

`ndt status` 逾時被停止時，那一次不算讀到：「是你的」和「measuring 是 nothing」都當成否。

## 5. 操作分頁與確認視窗

操作分頁有兩區：

- **claim／release**：claim 要填分鐘（1 到 240，預設 30）和備註（最多 200 字）；release 把 lab 提早還回去。
- **up／down**：up 選 plane（ovs 或 p4）和 hosts（ndt 的預設、4 或 128）；down 把 fabric 拆掉，永遠不帶 `--deep` 或 `--force`。

### 確認視窗

**每一個寫入**——這一頁的四個按鈕、Apps 的 start／stop、驗證格的重跑和逐步驗證——都先打開確認視窗：

1. **重新讀一次 lab**（plain `ndt status`），把 claim、measuring、declared 和槽位列在視窗裡。
2. **請伺服器預演**（dry run）：伺服器回答它實際會執行的指令，視窗裡「會執行」那一列就是伺服器給的；頁面自己不組指令。預演什麼都不執行。
3. **打字確認**：下面任何一種情況，都要在框裡打出指定的字（例如 `up`），「確認」才會亮：
   - 伺服器說這個寫入要打字（up、down、需要 lab 的驗證格重跑）；
   - measuring 不是 `nothing`；
   - 有 declared。
4. **「請先 claim」**：伺服器說這個寫入需要你自己的 claim（up、down、app 的 start／stop、需要 lab 的驗證格重跑），而 claim 不是你的時候，視窗會列出「請先 claim：claim 不是你的」，「確認」不會亮。
5. **共用狀態**：會改寫共用狀態的寫入（例如會暫時改寫 `host_count_override` 的那一格），要勾選「我知道這會改寫共用狀態」。
6. **防呆**：視窗打開時焦點在「取消」上；在「確認」上按 Enter 不會確認；「確認」只能按一次；按 Esc 等於取消。

### 誰在擋什麼

| 情況 | 誰拒絕 |
|---|---|
| up／down，claim 是別人的 | `ndt`（rc 5，refused） |
| up／down，沒有任何 claim | `ndt` 會放行；頁面比較嚴格，要你先 claim |
| app 的 start／stop，claim 不是你的 | 這個伺服器（409 claim），因為 `ndt` 的 apps 指令本身不檢查 claim |
| 需要 lab 的驗證格重跑，claim 不是你的 | 這個伺服器（409 claim） |
| 另一個 job 正在跑 | 這個伺服器（409 busy） |
| 打字確認、焦點、Enter | 只有頁面 |

送出之後，視窗下方的回應行會寫出結果；成功開始的 job 會自動在分頁下方打開它的 job 面板。

## 6. Apps 分頁

- 表格列出 `ndt` 認得的 app（伺服器啟動時從 `ndt` 讀出來的清單），每個 app 有 start 和 stop。
- **為什麼要先 claim**：`ndt` 的 apps 指令本身不檢查 claim，所以由 ndt serve 把關——它在佔住槽位之後重新讀一次 `ndt status` 的 claim 列，不是你的就回 409 claim，什麼都不執行。
- 下方是 `ndt apps status` 的原文，每 10 秒自動更新。

## 7. 工作紀錄分頁

- **每一個寫入都是一個 job**：伺服器馬上回一個 job id，由一個獨立的 runner 去跑。伺服器掛了，job 照樣跑完；伺服器重啟後找得回它。
- 表格欄位：短 id、種類、狀態、rc、rc_class、意思，最新的在最上面，每 10 秒自動更新。
- 狀態：
  - `running`：還在跑；
  - `finished`：結束了，rc 已記錄；
  - `orphaned`：runner 不見了，但 `ndt` 還在跑，仍然佔著槽位；
  - `lost`：結束了，但沒有人記下 rc。
- 按「開啟」會在**分頁下方**打開 job 面板，從任何分頁都看得到。面板列出種類、狀態、rc、argv，以及 stdout 和 stderr。
- log 每 2 秒增量讀一次，讀的是檔案，不會執行 `ndt`。下面三種情況停止讀取：
  1. job 不再是 `running`；
  2. 你按了「關閉」；
  3. 頁面在背景——回到前景後繼續。
- 從操作、Apps、驗證格送出的寫入，開始之後會自動打開它的 job 面板。

## 8. 驗證格分頁

**驗證格**是 `tools/test_workflow/live_cells/` 裡的回歸格子：每一格對應一個曾經在真的 lab 上看到紅、然後修好的問題。它們永遠留著，用來確認問題沒有回來。

表格的每一列是一格：名稱、一行說明它在驗什麼（滑鼠停在說明上，可以看 CELLS.md 的 expected 原文）、它需要什麼（`none`：不需要 lab；`idle`：lab 必須是關著的；`ovs4`、`p4-4`：這一格自己把那個 fabric 建起來），以及四個按鈕。第一次打開這個分頁時會讀一次清單，之後按「讀取驗證格」重讀。

### 四個按鈕

| 按鈕 | 做什麼 |
|---|---|
| **修前紀錄** | 修好之前的紀錄，應該是紅的。用這一格自己的 judge 讀 `old/` 這份 fixture：列出每一條 ASSERT、最後的 CELL: 行、失敗的那幾條是否正好等於人工審過的 EXPECTED-FAILS，以及 PROVENANCE.md（這些檔案從哪裡來）。只寫著「no such raw file」的紅，可能只是 fixture 缺檔，不是證據。 |
| **修好當晚** | 修好那一晚第一次變綠的紀錄（`new/`）。每一條都應該是 ok，最後一行是 CELL: PASS。這是當晚跑出來的，不是現在跑的。有些格子還沒有這份紀錄，按鈕會是灰的。 |
| **現在重跑** | 現在在 lab 上重跑這一格；需要 lab 的格子要先 claim。它是一個 job，結果看 rc_class：`pass` 是綠；`skip` 是沒有跑，不算通過；`fail` 是紅；`harness` 代表跑不起來或還原失敗，lab 不乾淨，要去看一眼。 |
| **逐步驗證** | 帶你走一遍：修前 → 修好當晚 → claim → 重跑 → 對照 → 你的判定。 |

### 逐步驗證怎麼走

完整的步驟是：`old` → `new` → `status` → `claim` → `run` → `release` → `compare` → `verdict`。不需要 lab 的格子沒有 status、claim、release；沒有 `new/` 的格子沒有 new。

- 每一步做完就停下來，每一步都寫著該看哪裡、綠長什麼樣子。按「下一步」（一樣會經過確認視窗）才往下走。
- **卡住**：一步沒成功，整個流程就停在那一步，並寫出原因。按「下一步」重試那一步，或按「中止」。claim 被拒絕就不會重跑；還原失敗就不會自動 release——lab 的狀態要讓你看到。
- lab 在對照和判定**之前**就還回去：判定看的是這次重跑留下的原始紀錄，不需要佔著 lab，而 lab 是大家共用的。
- **中止**不會 release 這次流程拿到的 claim；需要的話，自己到操作分頁按 Release。
- **你的判定**：最後一步由你決定。填備註（可以不填），按「判定：綠」或「判定：紅」，一樣要確認。
- 「逐步驗證清單」列出開始過的每一次流程，按「開啟」可以接著走。

## 9. 自動更新與暫停

- 頁面每 10 秒讀一次：`/lab`（執行一次 plain `ndt status`）、`/apps`（執行一次 `ndt apps status`）、`/health` 和 `/jobs`（這兩個不執行任何程序）。
- 上一次讀完才排下一次，不會疊加。所以頁面在前景、沒有量測時，每分鐘**最多** 6 輪；一輪約 1 到 1.9 秒，實際大約每分鐘 5 輪。
- 在這台筆電上量過（不用 strace：數 `/proc/stat` 的程序數，減掉等長的閒置窗口；sudo 經過記錄用的 shim；各 7 次）：
  - lab 閒置時，一輪約 596 個 task、10 次 `sudo`（8＋2）；
  - P4 fabric 開著、iperf3 在跑時，一輪約 719 個 task、8 次 `sudo`（6＋2），外加一次向 kernel 拿 `/ndt/get_graph_data`（curl，最多 5 秒；約 6 ms），也就是對正在受測的 kernel 做一次 northbound 讀取。
  - 這些 `sudo` 都只是列出或查狀態。

**已暫停（量測中）**

- 什麼時候：最近一次讀到的 measuring 不是 `nothing`，或有 declared。
- 暫停期間，頁面**每 60 秒只問一次「有沒有人在量測」**：讀 `/measuring`，也就是 `ndt status --measuring`。不讀 `/lab`、`/apps`、`/health`、`/jobs`。這是 Adam 的裁定：09-28 要量測中的自動探測唯讀、要輕；10-01 再規定探測只問有沒有人在量測。
- `ndt status --measuring` 只印 plain `ndt status` 裡的 declared 列和 measuring 列，由同一個 ndt 函式印出。它只讀 claim 檔和程序表：不用 `sudo`、不對 kernel 發請求、不查 OVS 或 bmv2。
- 成本（lab 閒置時量的，方法同上）：一次約 12 個 task、0.14 秒、0 次 `sudo`、0 次 curl；claim 有 declared 時約 17 個 task。量測中的狀態沒有量，從程式碼看只多掃一次程序表，一樣沒有 `sudo` 和 curl。換掉之前的探測是一次 plain `ndt status`：量測中每次約 564 個 task、6 次 `sudo`、一次向 kernel 拿圖。
- **怎麼恢復**：探測讀到 measuring 是 `nothing` 而且沒有 declared，就自動恢復每 10 秒一次；否則 60 秒後再探一次。探測逾時不算讀到，會繼續暫停，下一次探測再問。
- 所以如果量測沒有 declared，探測剛好落在兩段量測之間的空檔時，自動更新會恢復；下一段量測開始後，到某一次讀取看到它之前，可能會有一輪完整的讀取（約 719 個 task、8 次 `sudo`、一次向 kernel 拿圖）落在量測裡。量測期間要完全不讀，就先 declare。
- 探測不改任何分頁的內容：上方列的「上次讀取」一直是最後一次完整讀取的時間，暫停期間旁邊另外顯示「上次探測」的時間。
- 也可以隨時按「立即更新」：它把 lab、apps、health、jobs 全部讀一次，再由讀到的結果決定恢復或繼續暫停。
- 頁面在背景時連探測也停；回到前景後，60 秒後才探下一次，不會一回來就讀。

**已暫停（頁面在背景）**

- 什麼時候：你切到別的分頁、或把視窗縮小。
- 怎麼恢復：回到這個分頁時，頁面立刻讀一次，然後恢復計時——除非上一次讀到的是量測中，那就維持「已暫停（量測中）」，照上面的規則每 60 秒探一次。

**立即更新**隨時都能按，包括暫停中；讀取進行中時按鈕會暫時變灰。

暫停與否只看伺服器算好的欄位（`measuring_is_nothing`、`declared`），頁面不解析 `ndt` 的文字。

不會自動更新的：驗證格清單與逐步驗證（按按鈕才讀）；job 的 log 有自己的規則（第 7 節）。

## 10. 常見的回應碼

寫入之後，按鈕下方的回應行會寫出結果。成功時是狀態碼和開始的 job；被拒絕時是 `狀態碼 錯誤 -- 伺服器的說明`，例如 `409 claim -- ...`。

| 回應 | 意思 | 怎麼辦 |
|---|---|---|
| 202 | job 已經開始 | 看 job 面板 |
| 409 claim | 這個寫入需要你自己的 claim，而 claim 不是你的（或 claim 沒讀到） | 先 claim，或等對方 release |
| 409 busy | 另一個 job 正佔著槽位 | 等它結束；工作紀錄分頁看得到是哪一個 |
| 503 busy | 已經有兩個唯讀的 `ndt` 呼叫在跑，第三個等太久 | 稍後再試 |
| 400 refused | 參數不在伺服器允許的範圍內 | 看說明改參數 |
| 400 confirm | 這一格會寫共用狀態，但沒有勾選確認 | 重新送出並勾選 |
| 403 token／nonce／origin | session 的問題 | 執行 `ndt serve url` 重新進來 |

### rc_class：refused 和 dirty 的差別

job 的 `rc` 永遠是 `ndt` 真正的離開碼；`rc_class` 是伺服器依指令對它的解讀：

- **refused**（紫色）：守門的檢查說不，**什麼都沒做**。例如 up 在別人的 claim 下是 rc 5；claim 或 release 被拒是 rc 1。
- **dirty**（紅色）：`ndt` 做了、檢查了，**不喜歡它看到的**。例如 up 或 down 的 rc 1。lab 可能處在需要你看一眼的狀態。
- 這兩個是不同的問題（`ndt help`：「1 AND 5 ARE DIFFERENT QUESTIONS」），頁面永遠用兩種顏色，不合併。
- `ok` 是綠色；`report`（plain `ndt status` 只印報告、不判定）、`nothing`（沒有東西可處理）、`skip` 是灰色；`usage`、`unknown`、`signal`、`timeout` 是橘色。滑鼠停在標記上會顯示它的意思。

## 11. 安全上它保證什麼、不保證什麼

**保證**

- 只聽 `127.0.0.1`；Host 標頭必須是 `127.0.0.1:<port>` 或 `localhost:<port>`。
- 除了 `/health`，每個 API 請求都要 token；伺服器從不送 CORS 標頭，其他來源的請求一律拒絕。
- **token 不落地**：不在 localStorage、sessionStorage、cookie、頁面內容或網址裡。網址只帶一次性 key，打開就清掉。
- 載入頁面不寫任何東西：只有讀取，和一次換 token。
- 每一個寫入都經過確認視窗，要執行的指令由伺服器給。
- CSP：不允許 inline 的 script 或 style、不允許其他來源、不允許被別的頁面框住。這份手冊也一樣，它沒有任何 script。
- 頁面檔案在伺服器啟動時讀一次；每一次 `ndt` 呼叫都執行啟動時那一份 `ndt`。

**不保證**

- 同一台機器上、以你的身分跑的程式，讀得到 token 檔（權限 0600，預設 `~/.config/ndt-serve/token`），也就能做你能做的一切。
- 打字確認和焦點規則只是頁面的防呆，不是權限；拿著 token 用 curl 的人不會經過它們。
- owner 名字剛好叫 `yours` 的 claim，和你自己的分不出來（第 4 節）。
- 頁面只轉述 `ndt` 說的話；`ndt` 說錯了，頁面也跟著錯。
- 「開啟 Web-GUI」打開的是另一個 app，它的安全性不在這份保證之內。

## 12. 開啟 Web-GUI

- 網路拓樸和流量在 Web-GUI 裡看。按上方列的「開啟 Web-GUI」，會在新分頁打開它。
- 網址由伺服器決定：`ndt serve --webgui-url <URL>`，預設 `http://localhost:3000`（Web-GUI 在這台機器上的 Docker port）。只接受 http 或 https 網址；瀏覽器不存這個網址。
- 新分頁以 `noopener noreferrer` 打開：Web-GUI 拿不到這個頁面的任何東西，包括網址。
- Web-GUI 沒有在跑時，新分頁會顯示連不上；這不影響 ndt serve。
- 長期來看，ndt serve 和 Web-GUI 會合併成同一個 app；在那之前，兩邊各自獨立。
