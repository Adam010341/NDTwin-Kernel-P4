# NDTwin kernel log allowlist
#
# Purpose: make NEW warnings fail the build.
#
# Without this file, "check the log for warnings" degrades as soon as there are more
# than a handful -- a genuinely new warning gets lost among the ones you have already
# decided to live with. Here, anything not listed is a failure, so a regression cannot
# hide in the noise.
#
# Format (three fields, separated by a pipe WITH SPACES around it):
#
#   LEVEL | python regex matched against the message | why it is acceptable
#
# The separator is " | " (whitespace-pipe-whitespace), not a bare pipe, so that regex
# alternation still works: write it without surrounding spaces, e.g. (warn|error).
#
# LEVEL is one of:
#   WARNING  allowed at warning level; anything unlisted at warning level fails
#   ERROR    allowed at error level. Use sparingly and always with an expiry note --
#            an accepted error should be a bug with a ticket, not a permanent fixture
#   FORBID   fails if it appears at ANY level, including info/debug. For messages that
#            are quiet but mean something is badly wrong
#
# The regex is matched with re.search against the message text only (timestamp, level,
# file:line and function are stripped first), so no need to anchor it.
#
# Maintenance:
#   * check_logs.py reports entries that never matched, so stale lines get pruned
#   * to adopt this on an existing noisy log, run:
#       ./check_logs.py --suggest-allowlist <logfile>
#     then review each suggestion before pasting it in. Do not paste blindly: the
#     point is to decide which warnings are acceptable, not to silence all of them
#
# [Co-developed with claude code -- Adam]

# ============================================================================
# WHEN-POWERED-OFF: correct behaviour that only looks wrong out of context
# ----------------------------------------------------------------------------
# [Co-developed with claude code -- Adam] -- KNOWN-ISSUES A-8.
#
# These are NOT plain WARNING entries and must never be converted into any. A plain entry
# is a blanket permission, and each line below is *also* what a genuinely broken control
# plane produces. The scoped kind permits it only for the dpids --powered-off names; for
# any other switch it stays a full-volume failure, and with no declaration at all the run
# reports TOOL-PRECONDITION-FAILED (exit 3) rather than guessing.
#
# The pattern MUST capture the switch in a group named `dpid`; check_logs.py refuses to
# load one that does not.
# ============================================================================

WHEN-POWERED-OFF | reported a read failure for switch (?P<dpid>\d+) | the proxy cannot read a switch the Energy-Saving-App has powered down, and DeviceConfigurationAndPowerManager.cpp:1134 keeping the previous table is the correct conservative response. For a switch that is NOT powered off this is the 2026-08-07 wedged-controller defect (all ten switches reporting zero rules while s1 held 130) and must stay red
WHEN-POWERED-OFF | returned an empty flow table for switch (?P<dpid>\d+) after | same call site (DeviceConfigurationAndPowerManager.cpp:1146), the timeout branch: a powered-off switch's flow-stats reply legitimately never arrives. Unscoped, this is the lost-reply signal that the suspicion threshold exists to raise


# ============================================================================
# FORBID: quiet messages that mean real trouble
# ----------------------------------------------------------------------------
# These fail even at info/debug level, because their severity is not reflected in the
# level they are logged at.
# ============================================================================

FORBID | Unsupported SFlow Version | the sFlow emitter is producing malformed datagrams; the collector is discarding every sample
FORBID | Cannot open topology file | the kernel is running without its topology; the whole graph will be empty
FORBID | No matching node in JSON | a device rename targeted the wrong topology file (see issue 12 in doc/2026-07-27_p4_bmv2_support_plan.md)
FORBID | Failed to bind UDP socket | the sFlow collector port is taken; no telemetry will arrive at all
FORBID | Failed to create UDP socket | as above
FORBID | Exceed 100 hop \(potential loop\) | a forwarding loop in the computed path
FORBID | logger with name .* already exists | Logger::init called twice; a test suite is probably being skipped silently
FORBID | Cannot open OpenflowCapacity\.json | missing doc/2026-01-02_OpenflowCapacity.json; since W17 (2026-09-07) get_openflow_capacity still answers with the bmv2 plane, but the three vendor blocks are absent from the response

# --- client errors the L2 contract test provokes deliberately ---------------------
# [Co-developed with claude code -- Adam]
# Added 2026-08-07, when the first integration run failed the log check on 14 distinct
# messages and every single one was run_contract_test.py's own error-path probe. The
# test exists to send malformed input; the kernel is supposed to refuse it; refusing it
# is not a fault.
#
# These are WARNING rather than ERROR as of the same day: all three of the sites that
# used to log at ERROR answer 400, and logging a client error at ERROR is the same
# conflation as answering 500 for one. A kernel-side ERROR should mean the kernel has a
# problem, which is what makes the "error is never allowed" rule worth having.
#
# Note what this trades away: a real flood of client errors from a broken app is now
# quiet here. That is the right call for the log gate specifically -- it is the wrong
# tool for that job, and per-endpoint 4xx rates belong in the API metrics, not in a
# grep for the word error.
