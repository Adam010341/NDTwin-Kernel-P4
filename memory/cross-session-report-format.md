**Adam 2026-08-27 問：「他們傳給你的訊息會不會廢話也太多？以後第一句話就規定回報格式與字數限制？」**
直覺對了一半——**該協定的是格式，不是長度。**

## 🔴 為什麼字數限制會砍錯東西

實際查了當晚兩封 ~2400 字的報告，**幾乎沒有填充**。而那一晚每一個攔截，
都住在「只講重點」會判定成贅述的段落裡：

| 攔截 | 它在訊息裡的形式 |
|---|---|
| 「我**會**看到 rc=0 是推論不是量測」 | **一句但書** |
| 「drain-to-drain 與 start-to-start 平均相等 ⇒ 用錯的看起來完全正常」 | **一段推理** |
| 「那兩條測試是綠的，而它們釘住的正是缺陷本身」 | **一句背景** |

🔑 **但書、推理、背景正是字數壓力會優先刪掉的三種**，因為它們讀起來像鋪陳。
而這類工作的「重點」往往不是結論，**是結論旁邊那個限定條件**。

⇒ **限字數會讓報告變得更肯定、更好讀、而且更常是錯的。**

## ✅ 四段式（協定這個）

1. **要我裁的**（編號，通常 0–3 項）
2. **推翻／更正**（翻掉先前宣稱的，他們的或我的）
3. **交付**（commit、測試、閘門，一行一項）
4. **細節**（其餘；除非 1、2 引用到，讀的人可以跳過）

**長度不設限，但 1 和 2 必須在最前面。**
真正的成本不是字多，是**讀的人得全部讀完才知道哪幾段需要判斷**。
第 4 段的價值**在被引用的時候，不在被讀的時候**。

## 成本歸因（08-27 實測，推翻了我和 Adam 兩個人的假設）

- **跨 session 訊息不造成 cache miss。** 它們**附加**在 context 尾端，不使前綴失效。
  造成的是**永久性的 context 成長**：付一次寫入（1.25×），之後**每一個 request 再讀一遍**（0.1×）。
- 🔑 **所以換便宜模型當審查者不省我的錢**——訊息是誰寫的，不影響我讀它要付多少。
  換模型省的是**它產生內容**的成本。
- 當晚 43 則跨 session 訊息 ≈ 77k token ＝ context 的 13%，
  而 `MEMORY.md`（26 KB）只佔 1.47%。**真正的乘數是 598k context × 多步驟程序的 request 數。**
- ⚠️ **auditor 自己是最大單一貢獻者**（他發 2500–4500 字，對方 ~2400）。**規矩要從自己開始。**

## 為什麼他們字多，有一半是我造成的

每個決定都附理由，是因為 auditor 要求可否證的形式、會退件。那個要求買到了東西
（當晚 auditor 五個錯全被抓到），代價記在字數上。
⇒ **`CLAUDE.md` 一旦有了常規，他們可以引用而不必每次重新論證**——
那比限字數省得多，**而且不會砍到但書**。

## 🔴 2026-08-29：**只出現在通知裡的數字不可引用**——一次近失，差一步就進報告

`8/28 mainDev` 跑工單 ① 的最後一臂時，monitor 送來一則複驗事件：
`reps 0.1739,0.1284,0.0524`、`external=0.0331`。**格式完全正確、數量級完全合理、看起來就是結果。**

**那組數字在 repo 裡任何 log、任何 `arm.meta` 都不存在。**
真正的 `fast_b` 是 `0.2100,0.1101,0.1610`、`external=0.0491`。

**成因**：③ 和 ② 的 monitor **跑完之後沒有關掉**，還活著、還在送事件。
擋下它的唯一動作是：**三份 FINDINGS 的每一個數字都回頭從磁碟的 `arm.meta` 重讀過才寫下去。**

🔑 **為什麼這一類特別危險**：
- 通知**長得跟真結果一模一樣**——沒有任何欄位會說「我來自一個已經結束的 run」
- 它**抵達的時機**正好是你在等結果的時候 ⇒ 認知上完全吻合
- 它**沒有留下痕跡**：不像過期的檔案還能比對 mtime，訊息本身就是最終形態
- 多 session 之下，**每個跑完沒關的 monitor 都是一個潛在的假資料源**

⇒ **判準（兩條，缺一不可）**：
1. **通知只用來知道「該去看了」，不用來知道「看到什麼」。**
   任何要寫進報告／記憶／commit 的數字，**回頭從磁碟的正本重讀**。
2. **跑完就關掉自己的 monitor。** 留著的成本不是資源，是**它會在下一輪冒充證據**。

同族：[[verify-against-known-good-output]]（第七式「被作廢的檔案跟有效的長得一樣」——
這是它的訊息版，而且**更難察覺**，因為訊息連檔案系統的旁證都沒有）、
[[failures-that-report-success]]、[[evidence-must-outlive-the-handoff]]。
