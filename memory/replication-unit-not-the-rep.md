**2026-08-27，工單 P/Q 之間。我向審查員報「跨世代 `T` 差 42.2 ms、10.9 SE ⇒ 安靜臂不複製」。
他獨立重算，拿到同樣的 10.9，確認了。四十分鐘後第四臂進來，整個效應消失。**

## 發生了什麼

| | 我算的 | 正確的 |
|---|---|---|
| 分子 | 兩代安靜臂的差 42.2 ms | 同 |
| **分母** | **臂內 3 個 rep 的散佈**（SE 3.88） | **臂間散佈**（SE 24.9） |
| 結論 | Δ/SE = **10.9** ⇒ 決定性 | Δ/SE = **0.31** ⇒ 沒有差異 |

**一個臂裡的三個 rep 是「同一個臂的三次讀數」，不是「安靜條件的三個樣本」**
——它們共享那一臂的 fabric 狀態、鄰居、當下的一切。
⇒ 拿它們的散佈當**臂間**比較的誤差項，**低估約五倍**。

實測佐證：同一代的兩個安靜臂 `P_Q` 1001.7 / `P_Qp` 1043.3 ⇒ **差 41.6 ms**；
gen 1 的兩個差 27.2 ms。**臂間散佈本來就跟我宣稱的「效應」一樣大。**

## 🔑 為什麼這條特別危險：**獨立重算抓不到它**

審查員做了他該做的每一件事——重跑、逐格對、複核哨兵——**然後得到同一個錯誤答案**，
因為 **我們用的是同一份 rep**。

⇒ **「兩個人各自算出同一個數」證明的是算術，不是複製單位。**
⇒ 而本專案把「獨立重算」當成主要驗收手段之一，**這條是那個手段的已知盲點**。

## How to apply

1. **報任何 SE／t／Δ-over-SE 之前，先說出分母是什麼的散佈。**
   一句話：「這個誤差項是 ___ 之間的變異」。說不出來就是還沒想清楚。
2. **驗收問句：這三個數字，是同一個東西的三次量測，還是一個實例的三次讀數？**
   （對應到本 repo：一個臂裡的 3 個 `T` rep ＝後者；三個臂各一個 `T` ＝前者。）

   🔑 **審查員給的加強版，比我的好用**：
   > **「如果我改變其中一個數字，另外兩個會跟著變嗎？」**
   會跟著變（共享同一個臂的 fabric 狀態）⇒ **它們不是獨立複製，不能進同一個 SE。**

   這一版好在**它可以在腦中執行**，不需要先想清楚「複製單位」這個抽象概念。
3. **每格至少兩個臂，否則沒有誤差項可用。** 本輪安靜格恰好有兩臂才抓到，
   而**負載格每代只有一臂 ⇒ B14 那個「0.2 SE 完美複製」其實也無法量化**（同一個病，只是沒發作）。
4. 🔴 **不要用「別人重算過」當這條的防線。** 要重算的是**設計**，不是數字。

## 🆕 08-28：同一個錯**犯在儀器裡**，比犯在分析裡更難抓

先前的實例都是**分析**時把 rep 當複製單位（`10.9 SE` 其實 `0.31`）。
**這次是我把它寫進了量測腳本本身。**

`measure_bmv2_capacity.sh` 初版：**每個 rate 跑一次**，第一個 loss > 1% 的 rung 即宣告 drop onset。
它回報「**160 Mbit，工作點 56–64 M**」。

**交錯重測**（160/100/160/100/160/100）殺掉它：

| rate | 三次 loss |
|---|---|
| 160 | 0.358% / 0.501% / **0.067%** |
| 100 | 0.000% / 0.389% / 0.024% |

⇒ **同 rate 內的離散度與 rate 之間的差完全重疊**，而初版那個 **1.491% 一次都沒重現**。
📌 而且 **loss 非單調**（100M 0.399% > 140M 0.039%）⇒「第一個超過門檻的 rung」**不指向任何東西**。

🔑 **為什麼儀器裡更難抓**：**儀器不會告訴你它的 n 太小。**
分析時至少看得到「n=3」寫在那裡；腳本裡的 `for r in $RATES` 一次一格，**沒有任何欄位顯示 n=1**。
⇒ **解法是交錯重測（A B A B A B），不是加更多 rate。**

**重做之後訊號是真的**：640 M 兩次 33.6%/32.3%、1280 M 兩次 63.2%/60.8%，delivered 飽和在 ~430–500 Mbit。

## 🔴 08-29 反面：**複製解決不了量化。而我拿複製去當它的擋箭牌。**

前面整份講的都是「複製單位選錯 ⇒ 誤差項低估」。**這一條是相反的陷阱：複製做對了，但它對這個不確定性完全無效。**

工單 ① 的 R = fast/stock = 360/45 = **8.0**，而註冊邊界是 H1 ∈ [9,20] / H2 < 9。我寫：

> ~~「8.0 離邊界只有一階，但撐住它的不是餘裕是**複製**——六個 stock 臂全 45、四個 fast 臂全 360，零散布。」~~

**審查員直接推翻，他是對的。** 梯子量的是「loss ≤ 0.5% 的**最高階**」⇒ 真值落在**該階與下一階之間**：
stock ∈ [45,70)、fast ∈ [360,540) ⇒ **R ∈ (5.14, 12.0)——邊界 9 就在區間裡面。**

🔑 **十個臂落在同一階，只證明那一階穩定；對「真值在該階區間裡的哪個位置」零資訊。**
**不確定性的來源是量化，不是雜訊，而平均對量化無效。**

⇒ **驗收問句（跟本檔開頭那條並列）：**
> **「我的誤差是抽樣來的，還是刻度來的？」**
> 抽樣的 ⇒ 加臂會收斂。**刻度的 ⇒ 加臂一點用都沒有，只會讓錯誤的信心更整齊。**

📌 **零散布本身就是徵兆。** 六臂完全相同不是精度高，是**大家都被同一把粗尺量到同一格**。
與 [[instrument-must-not-mimic-its-own-finding]] 第四式「異常乾淨的判準讀數本身就是徵兆」同族。

### 而註冊時就該有一支「區間跨過邊界」的分支

PREREG §4 **自己寫過寬度**（「two rungs of resolution on a quotient is roughly ±45%」），
**卻只註冊了點估計的結局**（H1/H2/H3）。⇒ 缺陷在**決策規則**不在臂：
**H1/H2/H3 對點估計窮盡，對「區間跨過邊界」沒有一支。**
⇒ **任何比值輪都要註冊「不可分辨」那一支**，見 [[controls-decide-what-you-learn]] 的「以上皆非」。

### ✅ 收窄它的方法不是加臂，是用既有資料的**形狀**

**下一階超標多少，說明越過交叉點多遠。** stock 的下一階 loss 是 4.44/7.64/12.12/24.49%、
fast 是 25.80/26.62%（**每臂都跳一個數量級以上**）⇒ 兩側真值都貼在自己區間的**底部 ~11% 以內**
⇒ R ≈ **7.8**（更深進 H2，離比較好講的 H1 更遠）。
⚠️ **凸曲線上的線性內插給的是交叉點的下界不是估計值**，這是佐證不是量測。
正本 `doc/audit/2026-08-28_single-switch-build-ratio/FINDINGS-1b.md` §1.2–1.3。

## 🆕 2026-08-31：我把「相關觀察」當成獨立試驗，被 auditor 當場更正

F-5 細格輪要對「零幽靈」下上界，我建議用 rule of three：**每格 30 次 install ×
十個格點 ⇒ n=300 ⇒ ≤1%**。**錯的**——那十個格點是**同一次 install 沿時間軸的重複觀察**
（要量的就是「窗」，當然是同一事件看十次），不是十次獨立試驗。獨立單元＝**install**。
正解：把 N 從 30 提到 60（機時便宜），單臂 n=60 ⇒ 上界 ≤5%；跨臂併池只在兩臂皆零時
合法且須揭露跨兩個 fabric ⇒ n=120 ⇒ ≤2.5%。

🔑 **判準**：問「我把哪兩個東西當成可以相加的？它們之間有沒有共同的那一次事件？」
——這裡的共同事件就是那一次 install。**n 變大最舒服的方向，通常就是錯的那個方向。**
（同一週已犯過同型：把梯階格數當成資訊量。）
