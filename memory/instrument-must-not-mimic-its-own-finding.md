**原則（措辭出自 `8/27 mainDev` 寫在 `/sflow/stats` 的 docstring，審查員收進帳本）：**

> **一個儀器唯一不能有的故障，就是長得跟它自己的發現一模一樣的那個。**

⇒ 設計任何量測面時，**先問「它壞掉的時候會輸出什麼」**，若答案與「它要偵測的訊號」
序列化成同一個東西，那個設計就要改，**不是加註解說明、是改輸出**。

## 三次獨立應用（2026-08-27，同一天，三個 session 各自想到）

| 儀器 | 要偵測的訊號 | 壞掉時**天真的**輸出 | 改成 |
|---|---|---|---|
| `GET /sflow/stats`（我） | **送出端停了** ⇒ `samples_sent` 不再增長 | 未注入 emitter ⇒ 回 `{samples_sent: 0}` | **HTTP 503 ＋ "wiring failure, not a measurement of zero"** |
| `path` 非空比例採樣器（我） | **每條流都失去路徑** ⇒ 比例趨近 0 | fabric 上沒有流 ⇒ `ratio = 0.0` | **`ratio = None`**，並另記 `n_flows` |
| twin 讀數比對（`8/27 sampling`） | 分身停止更新 | 兩次快照相同 ⇒ 差分 0 ⇒ 看起來像「沒有流量」 | **回 `NO-DATA`，不回 0** |

🔑 **三次都是「0 是一個合法的量測值，也是失敗的預設值」**。
只要這兩件事共用同一個表示，**任何看到 0 的人都無法分辨**，而且**0 通常正是最有新聞價值的那個結果**
⇒ 儀器會在它最重要的時候騙你。

## 同一條原則的第四種形式：**數量不是身分**

突變閘門（`mutation-gate-for-tests`）是同一件事的變體：
`FAILED (failures=1)` 是真的紅燈，但**紅在別的測試上** ⇒
「閘門有效」與「閘門測到我以為的那條」共用同一個輸出。
審查員的收緊句：**紅燈的數量不是證據，紅燈的身分才是。**

## How to apply

1. **新儀器寫下來的第一件事是「它壞掉時輸出什麼」**，不是它正常時輸出什麼。
2. 若那個輸出**落在合法值域內** ⇒ 換一個值域外的表示：
   `None`／HTTP 錯誤碼／獨立的 `ok` 欄位／`n_flows` 這種分母。**不要用哨兵數值**（`-1` 會被拿去平均）。
3. **失敗要能被計數**：`poll_ok: false` 記成一列，而不是不寫那一列——
   「沒有那一列」與「那段時間沒事發生」同樣無法分辨。
4. 兩面都要驗：**接受面與拒絕面**。本 repo 有「八條拒絕路徑全綠而 accept path 100% 壞」的前例
   （[[smoke-the-accept-path-not-just-refusals]]），08-27 這三個是**反方向**——
   容易只驗接受面而不驗「壞掉時真的會大聲」。

相關：[[failures-that-report-success]]（母題）、[[mutation-gate-for-tests]]（第四形式）、
[[existence-is-not-wiring]]（沒接上的儀器回 0 就是這一族）、
[[verify-against-known-good-output]]（「看起來合理」零保護力，同一個理由）。

## 🆕 第五形式（08-27 傍晚）：**哨兵自己就是這個病**

工單①的哨兵：`|Q′−Q| > |B14−Q|/2 ⇒ CONFOUNDED`。**分母就是效應大小。**

⇒ 一個 B14 **幾乎沒動**的量（工單 P 的 `switch→host` ratio：`|B14−Q|` 只有 Q 的 **0.4%**）
會因為純算術理由被判 **🔴 CONFOUNDED** ——
**而那個紅燈讀起來正好是「這個量不可信」，實際上它說的是「這裡沒有效應可測」。**

**兩件相反的事共用同一個輸出。** 已改成 `|B14−Q| < 2%·|Q|` 時明說
「**NO EFFECT TO TEST，哨兵不適用**」，並印出兩個數字讓人自己看。

🔑 **這條原則會咬到執行它的那個工具本身。** 寫哨兵／閘門／判準時要多問一次：
**「當沒有東西可判的時候，它印什麼？」**

## 🆕 第六形式（同日）：**還在跑的臂 ＝ 提早結束的臂**

工單 P 的分析器對一個**仍在跑**的臂算出了完整的數字（169 s 視窗、真實計數器、
還進了哨兵印出 CONFOUNDED）。**「臂還沒跑完」與「fabric 提早安靜下來」序列化成同一份輸出**，
而後者正是要偵測的訊號之一。
⇒ 改成拿各臂 span 對中位數比，短的標 `INCOMPLETE` 並**排除在所有裁決之外**。
⇒ **通則：任何「部分完成」的狀態都要能與「完成了但值很小」區分開。**

## 🆕 第七形式（08-27 夜）：**儀器的解析度剛好等於門檻的粒度**

前六種都是「壞掉的儀器輸出合法值」。**這一種儀器完全正常**——
它只是**分不出「通過」和「失敗」**，因為兩者的距離小於它的最小刻度。

工單 S 的 poller 自證：註冊門檻「滿載下 sweep 間隔 **p95 < 3.0 s**」。
`poll_veth2.sh` v1 的時間戳用 `awk systime()` ＝ **整秒** ⇒ 量到的間隔**只可能是整數**。
實測 p95 **正好 3.000** ⇒ 註冊裁決 **FAIL**。

而真實 cadence 完全沒問題：A1 是 50 個「2」＋ 6 個「3」，**平均 2.107 s**
——那些 3 是**累積漂移的別名**（真實週期 2.05–2.11 s，整秒截斷每約十次多跳一格），
**不是停頓**。nearest-rank 的 p95 在 56 個樣本取第 53 名，正好落進那六個裡。

🔴 **而我在預註冊裡明文寫過「門檻 3.0 離預期值（2 對 ≥8）夠遠 ⇒ 量化不可能決定裁決」。
資料否證了那句話。量化正好決定了裁決。**

**處理方式（這條比結果重要）：修儀器，門檻一個字不改。**
ts 改 `date +%s.%N`，代價每 sweep 多一次 subshell+exec（2 次行程生成 vs 舊 poller ~320）
⇒ **被測的性質本身還在**。同門檻同負載重跑 ⇒ p95 **2.195 / 2.189**、最大間隔 2.22 s、
零個 ≥3 s。**第一輪的原始資料要留著——它是「為什麼換儀器」的證據，不是廢資料。**

### 🔑 由此得到的門檻紀律

> **註冊門檻時，要一併註冊「儀器在那個門檻附近的最小可分辨量」。
> 若它 ≥ 門檻與預期值的距離，這個測試還沒開跑就已經不可判。**

### 🔑 控制組在這裡救的不是結論，是「我有沒有資格下結論」

舊 poller（控制臂）的間隔是**連續值**（3.72、3.98 … 12.15）
⇒ **正好證明量化只發生在新 poller 那一側**。
**沒有那條控制臂，「只有 2 和 3」看起來就像正常資料。**
⇒ 併入 [[controls-decide-what-you-learn]]。

📌 附帶一個正向教訓：**別名解釋做了可證偽的預測，而且中了**——
從量化樣式推出真實週期「約 2.05–2.11 s」，換儀器後直接量到中位數 **2.10–2.13 s**。
⇒ **不是「換儀器數字變好看」，是舊資料的解釋預測了新資料的值。**
這正是 [[test-conclusions-by-using-them]] 的驗收方式。

## 🔴 08-27 夜：新形式——**儀器的解析度剛好等於門檻的粒度**

| 臂 | p95 | 間隔分佈 |
|---|---|---|
| A1 新 poller | **3.000** | 2 s×50、3 s×6 |
| A3 新 poller | **3.000** | 2 s×55、3 s×3 |
| A2 舊 poller（控制組） | 12.147 | 全部 ≥3.72，**連續值** |

新 poller 的時間戳是 `awk systime()`＝**整秒截斷** ⇒ 間隔只可能是整數 2 或 3。
真實週期 2.05–2.11 s 時，截斷每約十次 sweep 多跳一格 ⇒ **那些「3 秒」是累積漂移的別名，不是停頓**。
nearest-rank p95 在 56 個樣本取第 53 名，**正好落進那六個 3**。

⇒ **通過與失敗之間根本沒有可分辨的空間。** 宣稱很可能是真的，那一版儀器沒有能力顯示它。
（控制組 A2 是連續值 ⇒ **量化只發生在新 poller 那一側**。沒有 A2，「只有 2 和 3」會被當成正常。）

🪞 **共同來源才是機制**：門檻 3.0 是審查員從「sweep 間隔 2 s 的 1.5 倍」推的；解析度 1 s 是
`awk systime()` 給的。**兩個都是「秒」這個單位的產物 ⇒ 它們必然對齊，不是巧合。**
⇒ 可操作：**「門檻和儀器刻度用同一個單位表達 ⇒ 先假設它們會撞。」**

### 🪞 同一輪、審查員自己的版本：**統計量對它要防的故障是盲的**

工單 S §3/§7 我註冊「p95 < 3 s」。但這個閘門存在的理由是工單 N 那**一個 24.7 秒的洞**。
10 分鐘的階有 ~300 個 sweep，一個離群值排在第 285 名之後 ⇒ **p95 讀不到它**。
**我註冊的閘門，對它要防的那個故障是盲的。**

改成三條全要過：

| | 判準 | 防什麼 |
|---|---|---|
| a | **max 間隔 < 5 s** | 單一空洞（p95 看不到的那個） |
| b | **p95 < 3 s** | 整體節奏 |
| c | 🔴 **流量開始後前 30 s 內不得有 ≥3 s 的間隔** | **位置**——N 的洞正好落在起點 |

🔑 c 是這輪真正的教訓：**同樣大小的洞落在中段只是少算一點，落在起點整格作廢。
位置決定傷害，不只是大小。**

⇒ 驗收問句：**「這個判準能不能看見我怕的那個東西？」**
解析度那半與統計量這半是同一問的兩個答案（**一個是刻度太粗，一個是把它平均掉了**）。

### ✅ 順帶：**儀器改動的放行判準**（可重用）

跑完發現不過關就改東西，預設該被擋。這次放行是因為四條同時成立：

1. **門檻一個字沒動**——動的是「能不能分辨」，不是「過不過」
2. 改動理由是**先驗可驗、與想要的結果無關**的機制（整秒截斷）
3. 🔑 **新儀器比舊的兇**（每 sweep 多 2 次行程生成）⇒ 若仍過關，是保守方向的通過
4. 舊資料保留，且被指認為**「為什麼要換儀器」的證據**，不是失敗的草稿

🔑 **第 3 條最關鍵：問它讓結論更容易成立還是更難成立。**

### ✅ 上面那條被跑成 selftest 了，不再是主張

sFlow 用合成資料重建工單 N 的形狀（**300 個 sweep、一個 24.7 s 的洞放在起點**）：

```
one 24.7 s hole among 300 sweeps -> p95 2.000 s (PASSES the p95 gate, blind), max 24.7 s (gate (a) catches it)
```

⇒ **我註冊的 p95 閘門會讓那場災難整個通過，而讀數是 2.000——漂亮得像沒事發生。**
這個斷言現在跟著 `selftest_gates()` 每次跑。

🔴 **判準 (c)（流量開始後 30 s 內不得有 ≥3 s 間隔）他們刻意沒併進 `verdict()`**，
理由是它需要一個前兩條沒有的事實（流量開始的時戳）：
**若混在一起，一個拿不出時戳的階會「靜靜通過 (c)」——正是本檔的母題。**
現在拿不出時戳就回報 **N/A**，而且 selftest 兩個方向都驗（洞在開始後 5 s ⇒ FAIL、同一個洞在 200 s 後 ⇒ PASS）。

🔑 **可轉移**：一個需要額外事實才能判的判準，不要跟不需要那個事實的判準共用同一個回傳值——
**否則「缺資料」會被序列化成「通過」。**

## 🔑 08-27 深夜：**`destination paths: 9`，而那個 9 是 `len("Not Found")`**

mainDev 在驗證 fabric 收斂時打 `curl /ndt/get_all_destination_paths`，
parser 回報「**destination paths: 9**」。**端點 404，parser 把錯誤字串的長度當成計數。**
（正確來源是 proxy 的 `:8081/ryu_server/all_destination_paths`，正解 **16256 = 128 × 127**。）

**為什麼這是本族形狀最乾淨的一個：**

1. **失敗模式與發現序列化成同一個型別**——兩邊都是小整數，型別檢查、None 檢查、非負檢查全部無效。
2. **9 看起來完全像一個合理的壞掉的路徑數** ⇒ 它不會觸發任何「這數字怪怪的」直覺。
   而當時的脈絡正好是「twin 有沒有正確重新收斂」⇒ **它會被讀成「twin 壞了」並進報告。**
3. 🔴 **404 是一個成功的 HTTP 交易。** 沒有例外、沒有逾時、沒有非零 rc——
   **整條路徑上沒有任何東西失敗過。**

⇒ 第 3 點是可轉移的那條：**「這次呼叫有沒有失敗」與「這次呼叫有沒有回答我問的問題」是兩件事。**
HTTP／gRPC／CLI 都有大量「成功地告訴你它不知道」的回應。

**擋法**：對回應**先驗型別與結構**（是不是 JSON、有沒有那個鍵），**再取長度**；
或**餵已知輸入**（128 台 host ⇒ 期望 16256，是一道有已知答案的算術題）。
相關：[[failures-that-report-success]]、[[verify-against-known-good-output]]

### 🔑 08-29 續：**同一個讀數，一次是假象一次是量測，而差別不在讀數裡**

工單 ① 報 fast = 360 M。重跑（梯頂改由停止規則決定）之後**還是 360 M**。**數字從頭到尾沒動過。**

「走完清單」與「撞到停止規則」**必須是兩個不同的中繼資料值**——

⇒ **通則：任何「掃到某個條件為止」的迴圈，都要記錄它是因為條件成立而停，還是因為清單用完而停。**

投稿前置的三輪跑完之後回頭數，**每一輪的第一號威脅都是同一個：我們自己儀器的天花板會被寫成系統的天花板。**

|---|---|---|
| **③** flow-count | 梯子頂端（240 M/流）**低於交換機的能力** | 🔴 **發生了**——160 被當成「bmv2 的天花板」用了好幾天，還進了論文草稿與兩份 audit 文件 |
| **②** packet-size | **發送端**的 pps 上限會偽造「pps 恆定」這個頭條 | ✅ **擋住了**——註冊的 loopback 對照過關 9.6 倍（770.7 kpps 對要求的 80.0） |

🔑 **唯一擋住的那一次，是唯一「開跑前就註冊了對照」的那一次。** 另外兩次都是事後檢查抓回來的

⇒ **事後能抓到是運氣，不是方法。** 差別不在警覺性，在**有沒有把「如果限制是我自己」寫成一條要跑的對照**。

📌 **而這正是文獻的缺口**：我們審過的 18 篇報 bmv2 吞吐的論文，**每一篇都只給一個數字，

## 🏁 08-30：第一次量到「兩個要求互斥」的乾淨案例（梯子比要量的東西短）

128 hosts 的 P4 stack 上，R-2 的時間問題**結構性測不到**，而且能算出來：
* 一次取樣＝三個端點＝**735 ms**（`all_destination_paths` 自己 699 ms／931 KB／16256 條）
* 取樣器**正確地拒絕** `--interval ≥ 1.0`（「不能解析 1 Hz 的重算或 1 s 的消費者節奏」）
⇒ 需要 ≤500 ms，成本 735 ms ⇒ **不是努力不夠，是尺不對**。
解法不是加取樣、不是換安靜的機器，是**換工作點**：4 hosts 同一次取樣只要 **4 ms**（184×），
於是 1200 samples / **0 overruns** / 2.001 Hz，R-2 才第一次答得出來。
🔑 判準：**先看儀器自己的健康區段再看結果**。50% overrun 時那支分析腳本自己說
「timing 不是雜訊大、是不能用」——它救了我一次，因為我本來就想引那些區間。

## 🔴 08-30 夜第八式：**儀器自己的刷新週期，變成了發現的標題數字**

`FINDING-06_dispatch-is-a-10.7s-cycle-not-a-queue.md`（CONFIRMED、in-flight）量到派送窗
「10.70 s、sd 0.05」，並自報「週期來源沒在碼裡找到」。**在碼裡，而且不在 dispatch 路徑上**：

* `FlowDispatcher` **根本沒有時鐘**——`workerLoop_` 是 `cv_.wait` 醒來就送（`FlowDispatcher.cpp:109-130`）。
* 週期在**它用來讀「programmed at」的那個端點**：`GET /ndt/get_switch_openflow_table_entries`
  只回一份快取，刷新迴圈＝`DeviceConfigurationAndPowerManager.cpp:1900-1901`
  「`// 3. Sleep for 10 seconds` / `for (int i = 0; i < 10; ++i)`」，fetch `:1885`、整份覆寫 `:1890`。
* ⇒ **週期 = 固定 10 s + 一次南向 poll ≈ 10.7 s**，那 0.7 s 就是 10 台/1285 條的 poll 時間。
* 幻影則是 `HttpSession.cpp:1060-1061` 的 `// TODO: Immediately update the table` **在 HTTP
  執行緒上同步寫進同一份快取**——所以立刻出現、還帶著請求的 priority。

🔑 **決定性的辨識線索是「四條張貼時間相差九秒的規則，落地時間 0 ms 之內相同」**——
那不是「排程很準」，那是**同一次覆寫**。讀數的精度高過被測現象的精度時，先懷疑你在量單一事件。

**保住／不成立要逐句分**（[[disclosure-is-not-downgrading]]）：窗真實存在、上界、平均、相位分布、
「0 ms 同時落地」的觀察全保；**不成立的是機制與標題**——「dispatch cycle」、
「phantom ends exactly when programming begins」（結束的是快取覆寫，規則很可能早就編程了）、
「load cannot lengthen it」（固定的是 sleep，週期是 sleep＋poll，poll 隨規模長）。
差別很大：**「10.7 s 沒被編程」vs「10.7 s 看不見」**，嚴重度與修法都不同。

⇒ 🔑 **可操作，而且會一再用到：`/ndt/get_switch_openflow_table_entries` 是 10 s 快取，
不要拿它當時間戳。** 任何「X 什麼時候發生」的量測，只要讀這個端點，量到的都是快取刻度。
要問「何時真的編程」只能去南向側（proxy log／bmv2 table dump）。
⇒ 同型自問：**這個讀數的時間解析度是誰給的——現象，還是我的讀法？**
（那份文件自己抓到這型錯誤兩次——`spread` 統計量、`tr3_f5_window.py` 釘死在 priority——
第三次落在外面一層。**抓過這個病，不代表下一層不會再犯。**）

正本＝`doc/audit/2026-08-30_a7-dispatch-visibility/FINDINGS.md` §4。
相關：[[claim-verb-decides-the-evidence]]、[[arithmetic-that-fits-is-not-the-mechanism]]。

## 🆕 第九式（2026-08-31，遠端線自陳）：**量到的是啟動成本，卻當成頻寬報出去**

要估一段 2.5 GB 傳輸何時結束，該線用了一個**合成的小樣本**：8 MB / 21 s ⇒ 0.38 MB/s，
據此把時程區間放大到 110 分鐘。**實際 0.91 MB/s**（對**傳輸中的那個檔案本身**取兩次
size 讀數：557,580,288 B / 610 s），約 17:00 收工。

🔑 **錯在哪**：若真是 0.9 MB/s，8 MB 只需 9 秒，而他量到 21 秒
⇒ **那 21 秒裡大部分是連線建立與加速期**。樣本乾淨（`rc=0`）、方法正確、**只是太小**，
於是**啟動成本佔了讀數的一半以上，卻被當成穩態速率**。

⇒ **通則：拿來排時程的速率，樣本要大到啟動成本可以忽略；
而最好的樣本就是「那個真正在跑的東西」本身。**
（他手上一直有那個樣本，卻先用了一個合成的小樣本——同 [[replication-unit-not-the-rep]]
「複製解決不了量化」的鏡像：**這次是樣本太小而不是複製太少**。）

📌 連帶的操作習慣：**對長時間作業估 ETA，改用「對作業自身取兩點差分」**，
不要另跑一個 microbenchmark——後者一定含啟動成本，而長作業已經把它攤掉了。

## 🆕 第十式（2026-08-31，**設計時就攔下，還沒跑**）：儀器的簽章**數值上落在待測假說的註冊區間裡**

Adam 裁示為 ② 補一個 OvS 對照（近乎恆定的 pps 是 bmv2 的性質還是通則）。
原設計＝沿用 ③ 的 OvS fabric。**在寫預註冊時把帽換算成 pps，這一輪就死了**：

那座 fabric 戴 as-configured 的 **htb 1 Gbit 帽**（goodput ≈971 Mbit，出處＝
`2026-08-30_ovs-flowcount-control/FINDINGS.md` 的更正框，我讀過）。frame＝payload＋42 B：

| payload | frame | 帽對應 pps |
|---|---|---|
| 64 B | 106 B | 1145 kpps |
| 256 B | 298 B | 407 kpps |
| 1024 B | 1066 B | **114 kpps** |

**`114/1145 = 0.10`，而 ② 註冊的 H2（頻寬受限）區間是 (0.03, 0.12)。**

⇒ 🔴 **帽自己就是一條隨 frame size 下降的 pps 曲線，而且比值正好落在 H2 的接受區間內。**
跑在那座 fabric 上，這一輪**不會失敗，會產生一個看起來像發現的 H2**。

⚠️ **未驗證的那一半要標明**：我推論「OvS 跑得過那些 pps」的依據是研究報告裡
「08-28 jitter 輪同 fabric >1 Mpps 量級」的**轉述**，**我沒有重量**。
但這條推論對結論的方向不敏感——只要 OvS 在 256/1024 B 上構得到帽，陷阱就成立。

**修法**：改跑 unshaped fabric，並寫死「本輪與 ③ 的 OvS 臂不可比、不得並排」。
判準是「這一輪需要跟誰比較」——③ 需要兩平面同置放所以必須戴帽；
**本輪問的是平面內部的問題，不需要繼承那個組態**。

🔑 **可操作**：**設計任何「換一個平面／換一台機器重做」的對照，第一步是把兩邊
已知的儀器界限換算到同一個單位上，再看它們會不會撞到待測假說的區間。**
不要先假設「同一套梯階＝可比」。這一次算它只花三行除法，而它擋下的是一整輪。
