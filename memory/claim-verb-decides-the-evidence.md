2026-08-28 一天之內同型錯誤六次,分佈在三個完全不同的領域,所以它不是某個工具的怪癖:

| 我的宣稱 | 我拿的證據 | 那個證據實際證明的 |
|---|---|---|
| 「可以推到這個 repo」 | `git ls-remote` 成功 | 我**讀**得到它 |
| 「已發表的數字全都**不可複現**」 | 讀了 14 篇,沒人寫 build flags | 那些頁面上**沒寫**這件事 |
| 「fabric 跑的 bmv2 是這顆」 | `strings /usr/local/bin/simple_switch` | **PATH 上**那顆的內容 |
| 「這個檔已經 commit 了」 | 我記得我寫過它 | 我寫過它(實測 untracked) |
| 「kernel 死了」 | `pgrep -axf` 無輸出 | 沒有**整條 cmdline 完全相等**的 process |
| 「文獻裡沒有人揭露 build」 | 我的關鍵詞零命中 | 沒有人用**我的詞** |

**Why:** 每個宣稱裡都有一個隱含的動詞,而那個動詞規定了證據的種類。
**「不可複現」是要做才知道的;「不可比較」是看就知道的。我只做了看。**
同理:「可以推」要推過(或查 `permissions.push`),「跑的是哪顆」要問跑著的 process
(`sha256sum /proc/<pid>/exe`),「已 commit」要問 git(`git ls-files --error-unmatch`)。
用讀的通道回答寫的問題,失敗方向**永遠偏向「比較好講」**——六次沒有一次讓我的立場變弱。

**How to apply:** 把宣稱寫成一句話,圈出動詞,問「**要發生什麼事,這句才會是真的?**」
然後確認我手上的證據是那件事的產物,不是它的鄰居。做不到就**降級措辭到證據撐得住的那一句**
——降級幾乎總是還有一個很強的版本可用:「不可複現」降成「**互相不可比較**:表上任兩個數字
無法判定是否量了同一個東西」之後,論證反而更硬,因為它只依賴我真的做過的事(讀)。

📌 **副作用:我把沒查證的前提交給了 worker。** 我在派工 brief 裡寫「對照文件已 commit」,
實際 untracked——那個 session 花了額外一輪對帳才發現。**自己的錯會變成別人的起點。**
而諷刺的是同一天我才給繪圖腳本加了 `git ls-files --error-unmatch` 守衛,
**對圖的來源檔設了 git 守衛,對自己嘴巴講的來源沒有。**

## 🆕 08-31：我禁止的動詞是「併」，講出來變成「量」

跟 `bmv2論文審查` 交代新機器時我寫：「**那台跑出來的效能數字不能進報告／論文**」，
底下列三個理由。Adam 一句「為什麼說不能在遠端機器上量測效能」就戳破了——**三個理由裡
沒有一個支持那麼強的結論**：

| 我列的理由 | 它實際上禁止的動詞 |
|---|---|
| 「它是另一台機器」 | **併**（不能跨機器放進同一個比較）——不是**量** |
| 「它是 VM」 | **申報／控制**（絕對值會變、噪聲要交代）——不是**作廢** |
| 「binary 不同」 | **指名**（任何重編都一樣，跟機器無關）——完全不是機器的性質 |

🔑 **形狀**：三個各自成立的前提，推出一個比它們合起來還強的結論。每個前提都限制某個動詞，
而我在結論裡換成了範圍最大的那個。**這比「證據不足」更難自己發現**——因為每一條引用都查得到、
都對，錯的只有它們與結論之間的那一步。

⇒ 可操作：**寫下禁令之後，回頭問「這三條各自禁止的是哪個動詞？我的結論用的是哪個？」**
如果結論的動詞不在那張清單上，它是被我加上去的。

⚠️ 代價不是零：那句過寬的禁令會讓對方**丟掉一個其實可用的選項**——用第二個平台重現定性結論
是加分項（[[replication-unit-not-the-rep]]），而我把它跟真正該禁的「跨機器併數字」一起否掉了。
**過寬的禁令看起來安全，實際上是在替別人做他沒授權我做的取捨。**
