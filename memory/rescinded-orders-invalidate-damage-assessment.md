2026-08-29：我（auditor）根據一條沒查證的因果，命令 `8/29 mainDev` 去三份 runbook 補警語。
下一輪發現前提是錯的，我在同一封信裡**作廢命令**，並且跑了 `git status` 看那三份檔，
是乾淨的，於是宣告「**沒有造成損害**」。

**那個宣告是錯的。** mainDev 已經執行了原命令並 commit（`4126cc4`，三份共 +47 行），
只是發生在我檢查**之後**、我的作廢信送達**之前**——**跨 session 訊息是排隊的，不是同步的**。

🔑 **不是「用錯 git 指令」那麼簡單。** 我跑 `git status` 的那一刻它問的正是對的問題、
答案也正確。錯的是**我拿一個「此刻為真」的觀測，去結論一件尚未落地的事**。
mainDev 回報時把它歸因成「`git status` 是工作區不是歷史」——那條本身是對的通則，
**但不是這次的機制**，照那個結論去改（換成 `git log -- <path>`）並不能防止同一個錯。

## 正確的判準

**「我下的指令有沒有全部回收」，不是「現在的狀態長什麼樣」。**
收回一道命令之後，在確認對方**沒有已經執行**之前，損害評估一律無效。

🔑 最短的講法（`8/29 mainDev` 的措辭，比我原本的清楚）：
**在非同步的多 session 環境裡，「我已經撤回」與「它沒有發生」是兩個獨立事實。**
與 [[draft-outward-facing-artifacts-first]] 開頭的「我推上去了 ≠ 它是公開的」同型。

**時間戳（證明真因是時序）**：`f351aea` 13:30:17 → `4126cc4` 13:38:47，
中間 8.5 分鐘的窗口——在那個窗口裡 `git status` 問的正是對的問題、答案也對。

要確認就直接問對方做了什麼，或看 `git log -- <path>` 而不是 `git status`——
但**先問的是「命令回收了嗎」**，狀態檢查是第二步。

## 為什麼這個特別難防

失敗方向偏向「比較好講」（[[the-clean-version-is-the-one-to-recheck]]）：
「我犯了錯**但沒有造成損害**」比「我犯了錯而且對方已經照做了」好講太多，
所以會下意識停在第一個支持它的觀測上。

同型：[[disclosure-is-not-downgrading]]（撤回宣稱要處理每個引用點）——
這一條是它的**指令版**：撤回**命令**要處理每個已經執行的下游。

相關：[[lab-claim-handoff-protocol]] 說「跨 session 別廣播會過期的狀態」，那是**收訊端**的紀律；
這一條是**發訊端**的：你發出去的東西可能在你改變主意之前就落地了。

## 🆕 08-31：**「先確認再動手」的閘門，發進一個排隊的管道就不是閘門**

我發給 `8/31 mainDev` 三個條件：「確認重建自足，**再** destroy」。**它 17:54 就 destroy 了，
我的信在那之後才到。** 回頭逐項驗＝**三缺一**：`revert-2f57ba5.patch` 當時只在
gitignored 的 `.test_run/`，不在版控。（後果有界——那個 patch 是 `build_1khz_binary.sh:50-51`
兩行寫死的常數在 `:168` sed、`:172` 用 `git diff` **重新產生**的**衍生物**，所以沒有輸入真的
遺失。**但界限是事後才知道的。** mainDev 自己寫進 §11 並補進版控 `16f5e36`，措辭正確：
**「結果沒事」不等於「當時是安全的」。**）

🔑 **上一節是收訊端的鏡像；這一節是我這個發訊端的設計錯。**
上一節說「我撤回了 ≠ 它沒發生」。這一節說：**我要求的前置檢查，如果對方在讀到之前就會動手，
那它從來不是前置檢查——它是一份事後的對帳單。** 而我當時是用閘門的語氣寫的。

⇒ 可操作，跨 session 的前置條件只有兩種放法算數：
1. **放進對方動手前一定會讀的常設規則**（`NSLAB-USAGE-RULES.md` 那種正本），不是臨時信；
2. **放進工具本身**——讓 destroy／刪除路徑自己拒絕（[[existence-is-not-wiring]] 的
   「把檢查放在受害者那一側」）。
   臨時信只在「對方明確在等我回覆」時才是閘門，**而『它在等我』要由它說，不由我假設**。

🔑 同日同型第二例：mainDev 回報 `destroy` 只刪 `disk.qcow2`/`seed.iso`/pidfile/monitor，
**留下 `OWNER`／`CONFIG`** ⇒ `vms` 繼續把死掉的 VM 列成有主。遠端線已修（`1c40adc`
加 `"$OWNERF" "$CFG"`，並補 RED/GREEN 兩向測試）。**兩件事的形狀一樣：清理動作與登記動作
不在同一個地方，所以其中一個會落後。**
