2026-08-28。Adam 提議「用一個沒有先備知識的模型跑一次安裝指令，這樣它就不會有很多先備知識」。
這個提議是對的，而且它抓到的東西我自己跑兩天沒看到。

## 我的乾淨室測試結構上看不到什麼

**它證明的是「這串指令跑得動」，不是「照著讀的人能不能做到」。** 兩個原因：

1. **我的 harness 每條指令都帶絕對路徑或自己 `cd`**（因為腳本本來就該這樣寫）。
   ⇒ **「繼承上一步工作目錄」造成的缺陷對它 100% 隱形。**
   真人會停在上一個指令留下的 cwd，腳本不會。
2. **我每次遇到含糊都用先備知識默默補上**——我知道 `DEBIAN_FRONTEND` 是什麼、
   知道要看產物不看 rc、知道 `conda activate` 只在當前 shell 有效。
   **補得越順，缺陷越看不見。**

## 實例：一條四步驟的 cwd 陷阱鏈

官網手冊裡，兩個外部模型（DeepSeek、Muse Spark）**獨立地**都指到：

```
§4.2 步驟 2:  mkdir build && cd build     ← 從此你在 build/ 裡
§5:           nano testbed_topo.py        ← 沒有 cd ⇒ 建在 build/
§6.1:         git clone p4-guide          ← 沒有 cd ⇒ 整套工具鏈源碼在 build/
§6.4:         「重複 §4.2」                ← 而 §4.2 步驟 2 的第一行是 rm -rf build
```

**每一步單獨看都沒問題，串起來會把一兩小時的建置成果刪掉。**
我的 harness 從沒踩到，因為它每一步都自己 `cd` 到絕對路徑。

## 方法：兩條並行，不要只做一條

| 做什麼 | 用誰 | 為什麼 |
|---|---|---|
| **只讀文件、找「這步假設你已經知道什麼」** | 外部模型（DeepSeek／Muse，**沒有 shell**） | 便宜、不碰環境、可並行；正好是它們做得到的事 |
| **真的執行** | 全新的 Claude subagent，prompt 限制死 | 只有它有手 |
| **真人讀得懂嗎** | Adam 自己裝一遍 | 前兩者都取代不了 |

🔑 **產生效果的是 prompt 的那一句，不是換更笨的模型**：
> **「你不准用這份文件以外的知識填補空白。如果某一步只有在你剛好已經知道某件事時才成立，那就是發現。」**

太弱的模型會產生大量假問題（被本來很清楚的東西搞混），真發現反而被埋掉。
見 [[review-prompt-shape-beats-model-choice]]。

## 🔴 收到的結果一定要對帳，兩個模型都給了假陽性

- **DeepSeek**：宣稱 `pip install "dnspython<2.3"` 不可能產生文件寫的 `1.16.0`
  （`<2.3` 會選 2.2.1）。**推理合理、結論錯**：`eventlet==0.30.2` 會先把
  `dnspython 1.16.0` 拉進來，後面那行變成「已滿足」。**我是拿前一天真跑的 log 對帳才推翻的。**
- **Muse**：把兩個 `{{< codefile >}}` shortcode 判成「程式碼沒有提供」。
  **那是我的 prompt 造成的**——我餵原始 markdown 而不是算繪後的頁面。
  ⚠️ **審查外部產出時，先問「這條是不是我給的輸入造成的」。**

⇒ 11 + 10 條裡，**收斂的 5 條全部成立**（兩個模型獨立指到同一處＝強訊號），
獨有的那些對半分。**先修收斂的。**

## 🔴 2026-08-28：**harness 與讀者拿到的根本不是同一個檔案**——比 cwd 那條更根本

安裝手冊 §2.6 叫讀者**從網站貼**一份 `intelligent_router.py`（724 行），
§4.1 才叫他 **clone** repo（那份 2084 行）。而使用手冊用**裸檔名**啟動
（`ryu-manager intelligent_router.py`，相對 cwd）。

⇒ **讀者跑的永遠是自己貼的那份，從來不是 clone 下來的那份。**
兩份同名、沒有任何一句話說它們不同、VM-Linux 頁還有第三個名字。

🔑 **而所有自動化檢查——包括我的——都是 clone repo 來測的。**

> **測試 harness 用 clone 取得檔案，讀者用貼上取得檔案，
> 所以 harness 測的那份沒有任何讀者會拿到。**

⇒ **在 harness 裡加多少斷言都揭不出來，因為 harness 站在分裂的另一邊、手上根本沒有那個受測物。**
可操作的通則：**當文件叫讀者用「和你的測試不同的途徑」取得某個東西時，你的測試就不是在測讀者的那一份。**
修法不是加嚴 harness，是**消除分裂**（§2.6 移到 §4.1 之後只留一份；或啟動指令改絕對路徑）。

📌 而這次的具體後果是**反直覺的**：**手冊是對的，正因為 snippet 是舊的**——
repo 那份的 `is_mininet` 被 L602 無條件覆寫（檔案自己註明「改這行沒有用」），
網站那份只賦值一次、真的生效。**「同步 snippet」會把一個假旋鈕散進官網。**
⇒ 🔑 **文件與被描述物的漂移，方向可以是讓文件變得更對而不是更錯。
看到漂移的第一個動作是問「哪一邊錯了」，不是「怎麼對齊」。**

> **「先同步」是唯一在兩種答案下都錯的選項。**

⇒ **兩個分支都需要我們三個 session 都沒有的知識**（那座 HPE 測試床）。
🔑 **這把「文件 vs 程式碼要對齊哪一邊」變成了「這是原始碼問題不是文件問題」**——

留著的是「兩份同名檔、測試看不見」這個結構性問題。
